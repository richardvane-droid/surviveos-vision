🎬 沉浸式想象

地堡储藏室隔墙背后那个 60cm 宽的型材机架上，三台机器的指示灯在暗处一闪一闪：最下面是四盘位 NAS，中间是合上盖子的 Windows 笔记本，最上面是一台没接显示器的 M1 Mac mini。你在木屋吧台边翻手机，看到一条推送：“0603 雨水罐水位传感器 40 分钟没上报。”点进去，是 Uptime Kuma 的红条，旁边是 Beszel 画的三台机器的温度曲线，一切正常，只是那个传感器电池该换了。晚上你在地堡沙发上按下观影场景，Jellyfin 从 NAS 上把电影推到 98 寸电视，声音从大柏林音响出来；而那台 M1 Mac 正在后台默默给今天草地摄像头拍的 3,000 张照片跑识别，把“来了一只白鹭”写进日志。

✅ 设想方案清单

  1. 四盘位 NAS（2×8TB 镜像 + 2×4TB）做全屋存储：影音库、照片库、每个模块的数据库快照，走 2.5GbE
  2. 旧 Windows 笔记本当“常年在线的 x86 工人”：跑 HomeAssistant（Docker）、ESPHome 编译、Uptime Kuma；自带电池就是 UPS
  3. M1 Mac mini 无头运行：跑图像识别（0604 的鸟、0801 的物品识别）和 Immich 的机器学习，功耗只有十几瓦
  4. 三台机器 + 交换机 + 光猫全放地堡储藏室隔墙背后的 2020 型材机架上，一根 2.5GbE 到 0802 屏墙的小主机
  5. 全屋智能监测：每个模块的传感器/设备在 HA 里都有“最后上报时间”，超时就红，Uptime Kuma 盯服务，Beszel 盯机器
  6. 每天凌晨 NAS 快照 + 每周一份冷备到阁楼保险箱里的硬盘；断电时笔记本电池撑 HA 两小时
  7. 此前写着树莓派的模块（0201 / 0802 / 0103 / 0601～0603）统一改口：主机就是这三台，树莓派退回传感器节点

🔥 小红书灵感点

  • 小红书「家庭机房」帖的精髓是灯光和整齐走线：机架用黑色型材，网线全部同色，指示灯朝外
  • 「去家务化」：所有备份、更新、告警都自动跑，每周只看一封汇总
  • 「精神领地」：机房只有自己一个人能进 Web 面板，账号一个，2FA 开着

⚠️ 避坑提醒

  • NAS 不是备份，镜像盘只防单盘坏，真备份是那块每周拿去阁楼的冷盘
  • 储藏室潮，机架底下垫高 10cm 并和 0203 除湿联动，湿度 >65% 先降湿再开盘
  • M1 Mac 无头启动要设自动登录 + 断电自启，不然一次停电就变砖头躺着

🔧 GitHub 上的成熟方案

按知名度（星数）优先、有中文版优先挑的开源项目，每个都在 2026-09 打开核实过存在。每个方案配一段科普介绍和一张铅笔风的“它怎么工作 + 怎么接进本模块”示意图。

louislam/uptime-kuma ★ 90.1k 界面有中文

自托管的服务监控面板：HTTP / TCP / DNS / Docker / 推送等监控类型，90 多种通知渠道和状态页

→ 盯全屋服务：HA、Jellyfin、NAS、每个 ESPHome 节点的心跳，掉线就推手机

Uptime Kuma 是自托管服务监控面板里最受欢迎的一个，由 Louis Lam 开发，90.1k 星。它解决的问题很单纯：我的服务还活着吗，挂了赶紧告诉我。

它的工作方式是：为每个目标建一个监控器，类型有 HTTP(s)、关键字、JSON 查询、TCP 端口、Ping、DNS 记录、Docker 容器，以及反过来的推送型：目标定时向它报到，超时没来就算掉线；最短 20 秒探测一次，连续失败达到阈值就通过 90 多种通知渠道推出去（邮件、Webhook、Bark、钉钉都有）；还能生成对外的状态页、看证书到期、画延迟曲线。界面通过 Weblate 有完整简体中文，README 是英文。

在 0804 里它跑在那台常年在线的 Windows 笔记本的 Docker 里，盯全屋服务：HA、Jellyfin、Immich、NAS 的 SMB、Beszel 本身都是 HTTP 或 TCP 监控器；每个 ESPHome 节点建一个推送监控器，节点每 5 分钟往它打一次心跳，40 分钟没上报就红；通知走 Webhook 推到 HA 的 webhook 触发器，由 HA 统一分级再转手机。注意它自己也可能挂，所以让 HA 的一条自动化反过来每小时探它一次，两边互相盯着。

henrygd/beszel ★ 24.3k 界面有中文

轻量服务器监控：Hub + Agent 架构，历史曲线、Docker 容器状态、温度、S.M.A.R.T. 和告警

→ 盯三台机器本身：NAS 盘温、笔记本 CPU、Mac mini 内存，一个面板看完

Beszel 是一个轻量的服务器监控系统，Go 写成，24.3k 星，只做三件事：历史数据、Docker 容器状态、告警。它解决的问题是家庭机房那几台机器到底健不健康。

它的架构是 Hub 加 Agent：Hub 是基于 PocketBase 的 Web 应用，自带数据库和用户系统；Agent 是一个小二进制，装在每台被监控的机器上，向 Hub 上报 CPU、内存、磁盘用量与 I/O、网络带宽、温度传感器、S.M.A.R.T. 健康，以及每个 Docker 或 Podman 容器的资源；Hub 画曲线、存历史，超过阈值就发通知，支持 OAuth 登录和自动备份。Agent 有 Linux、macOS、Windows 版本。界面通过 Crowdin 有简体中文，README 英文。

在 0804 里它管三台机器本身：Hub 跑在笔记本 Docker 里，Agent 分别装到 NAS（Docker 版）、笔记本和 M1 Mac mini（Homebrew 版），一个面板看 NAS 盘温和 S.M.A.R.T.、笔记本 CPU、Mac 的容器负载；盘温超 45℃ 先推告警，再联动 0203 除湿。告警同样走 Webhook 进 HA。注意 Mac mini 无头运行时 Agent 要用 launchd 开机自启，否则停电重启后就没数据了。

jellyfin/jellyfin ★ 54k 界面有中文

自由软件媒体系统，服务端 + 各平台客户端，ffmpeg 硬件转码，Plex / Emby 的开源替代

→ NAS 上的影音库靠它推到地堡 0207 的 98 寸电视，硬件转码走 Mac mini 的 VideoToolbox

Jellyfin 是自由软件媒体系统，2018 年从 Emby 闭源时分叉出来，.NET 写成，54k 星，没有付费层、没有云账号，是 Plex 和 Emby 的开源替代。它解决的问题是：把 NAS 上的电影、剧集、音乐和照片整理成有海报有元数据的库，推到家里任何一块屏幕上。

它的架构是服务端加客户端：服务端扫描媒体目录、从 TMDB 等抓取元数据、管理用户和播放进度，通过 ffmpeg 做转码，支持 QSV、NVENC、VideoToolbox 等硬件加速，编码格式和码率按客户端能力实时协商；客户端有网页、Android / iOS、Android TV、Apple TV等，还有 REST API 和插件系统。2026 年 6 月发布 10.11.11，Weblate 有完整简体中文界面，官方文档英文。

在 0804 里它的服务端直接装在 M1 Mac mini 上，媒体目录经 SMB 挂 NAS 那 2×8TB 镜像盘的影音库，转码用 VideoToolbox，NAS 的弱 CPU 不用碰转码。地堡 0207 的 98 寸电视上装 Android TV 客户端，HA 的 media_player 集成接它，按下观影场景就自动调暗灯、接着上次进度播。注意用户账号只开一个，2FA 靠反向代理补上；Mac 要设自动登录和断电自启。

awesome-selfhosted/awesome-selfhosted ★ 318.1k 无中文 延伸

自托管软件的总清单：几百个可以架在自己服务器上的免费软件按类别整理，每条一句话加许可证和语言，配套网站可筛选

→ 全屋存储和智能落地后，每个模块都会提出要一个什么什么服务的需求，先来这张地图上找，再决定装哪个

awesome-selfhosted 是 GitHub 上最著名的清单类仓库之一，318.1k 星，从 2015 年维护至今。它解决的问题是：想用自己的服务器替代某个商业云服务时，不知道有哪些开源选项，也不知道哪些还活着；这份清单把几百个可自托管的软件按类别排好，每条一句话、许可证、实现语言和是否依赖非自由组件。

它在清单类项目里算严谨的：条目数据放在单独的 awesome-selfhosted-data 仓库里，每个软件一个 YAML 文件，主仓库的 README 和网站 awesome-selfhosted.net 都由脚本生成。收录有门槛，要求项目至少四个月历史、有活跃更新、有可用文档；每年清理一年以上没有提交的项目，所以列表里的东西基本都还能用。网站版可以按类别、许可证、语言筛选，还能看星数和最近更新时间。

社区靠拉取请求维护，条目变更每周都有；没有官方中文版，但国内有志愿者的转译仓库，以及大量以它为蓝本的自托管推荐文章。

在 0804 里它是延伸，用法是当作一张采购地图。这套系统里每个模块都会提需求，0107 要菜谱管理、0104 要相册、0209 要笔记、0704 要语音合成，每次先在这张清单对应的类别里找，按活跃度和是否有 Docker 镜像挑两三个试，选定后在 0804 自己的一张已部署清单里记下服务名、跑在哪台机器、端口、备份策略。三台机器能承载的服务有限，这张清单帮你比较，那张清单帮你克制。

portainer/portainer ★ 38.2k 无中文 延伸

Docker 与 Kubernetes 的网页管理台：容器、镜像、卷、网络一目了然，Compose 文件当 Stack 部署，Agent 模式把别的机器纳进同一个界面

→ 笔记本和 NAS 上加起来十几个容器，靠命令行记不住；一个网页看日志、重启、更新，手机上也能操作

Portainer 是 2016 年开始的 Docker 管理界面，38.2k 星，社区版免费开源，商业版收费。它解决的问题是：Docker 命令行对偶尔维护一次的人不友好，忘了容器名、找不到日志都要查文档；Portainer 把这些变成网页上的按钮。

它自己也是一个容器，挂上宿主机的 Docker 套接字就能管理本机；要管别的机器，在那台机器上跑一个 Portainer Agent，主界面加一个环境就纳进来。每个容器能看实时日志、进终端、看资源曲线、改配置后重建。最常用的是 Stacks：把 docker-compose.yml 贴进去或指向一个 Git 仓库，一键部署整组服务，Git 模式还能定时拉取自动更新。

它是家庭服务器圈子里的标配；界面没有官方中文，但社区有汉化版镜像，国内教程极多。轻量替代品有 Dockge，功能不如它全。

在 0804 里它是延伸：Windows 笔记本上的 Docker 装 Portainer 主程序，HomeAssistant、ESPHome、Uptime Kuma、Beszel Hub、homepage 各写成一个 Stack，Compose 文件放在 NAS 上的一个 Git 仓库里，改了配置推一下就自动重建；NAS 自带的 Docker 跑一个 Agent 纳入同一界面，Jellyfin、Immich 在那边。出门在外收到 Uptime Kuma 的红条，手机打开 Portainer 看一眼日志、点一下重启，多数小故障就解决了。

syncthing/syncthing ★ 88.3k 界面有中文 延伸

点对点的连续文件同步：设备之间直接加密传输，没有中心服务器，改了就同步，带版本保留；手机、电脑、NAS 都有客户端

→ 手机照片进 NAS、阁楼电脑的打印文件到 Mac mini、各模块的配置目录到冷备盘，这些日常搬运交给它，人不用再插线拷

Syncthing 是 2013 年由瑞典开发者 Jakob Borg 发起的开源同步工具，88.3k 星，是自托管圈里替代网盘同步功能的头号选择。它解决的问题是：多台设备之间的文件想保持一致，但不想经过任何一家公司的服务器。

它的架构是纯点对点的：每台设备有一个由证书派生的设备 ID，两台设备互相添加并共享某个文件夹后，就直接建立 TLS 加密连接，用块交换协议只传变化的块。局域网内靠广播互相发现，跨网络用公共发现服务器交换地址，穿不透 NAT 就走志愿者的中继，中继只转发密文。文件夹可以设成只发送、只接收或双向；版本控制能把被覆盖和删除的文件留几份；忽略规则用类似 gitignore 的语法。它是一个 Go 程序加网页界面，安卓有官方客户端，NAS 系统大多有套件。

项目十多年持续发版，2026 年仍是月度更新；网页界面翻译完整，含简体中文，中文教程很多。要记住它是同步不是备份，误删会同步到所有设备，所以要配合版本控制或专门的备份工具。

在 0804 里它是延伸，负责日常搬运：手机相机目录只发送到 NAS 的照片库，Immich 在 Mac mini 上再去索引；阁楼工作站的 3D 打印文件夹和 Mac mini 双向同步；笔记本上 HomeAssistant、ESPHome 的配置目录只发送到 NAS，NAS 快照之后再由 restic 做真正的备份。设备只有三台机器和一部手机，发现和中继都关掉，只在局域网里走。

restic/restic ★ 35.6k 无中文 延伸

快、安全、省空间的备份程序：内容去重、全程加密、每次备份一个快照，仓库可以放本地盘、SFTP 或任何 S3 兼容存储

→ NAS 快照挡不住整机损坏，每周冷备到阁楼保险箱那块硬盘需要一个真正的备份工具，能去重、能校验、能只恢复一个文件

restic 是德国开发者 Alexander Neumann 在 2014 年发起的备份程序，35.6k 星，用 Go 写成，单个可执行文件。它解决的问题是：备份工具要么复杂得像企业软件，要么只是复制文件；restic 把去重、加密、增量、校验这几件正确的事做全，命令却只有几个。

它的模型是仓库加快照：初始化仓库时设一个密码，之后所有数据在写入前都加密。每次 backup，文件被切成内容定义的变长块，只有仓库里没有的块才上传，所以第二次备份只传变化的部分，同一份文件在不同路径也只存一次；完成后生成一个快照。恢复可以整份还原，也可以把快照挂载成文件系统去翻某一个文件；prune 按策略清理旧快照，check 校验完整性。后端支持本地目录、SFTP、S3 兼容对象存储和 rclone 支持的一切。

项目十年稳定，2026 年仍在发版；文档是英文，中文教程主要在自托管社区里。

在 0804 里它是延伸，接在 NAS 快照后面。方案说每天凌晨 NAS 快照、每周一份冷备到阁楼保险箱的硬盘：快照解决误删和回滚，restic 解决整机损坏和火灾。做法是笔记本上定时跑 restic，源是 NAS 上的照片库、各模块数据库快照和 HA 配置，仓库一是那块每周插一次的冷备硬盘，插上后自动补齐；仓库二是一个便宜的 S3 兼容对象存储，只放最要紧的几十 GB。每月做一次恢复演练，随机挑一个文件从冷备盘里取回来，确认密码没忘、仓库没坏。

n8n-io/n8n ★ 198.3k 无中文 延伸

可自托管的工作流自动化平台：拖节点连线，四百多种集成加代码节点，Webhook 触发，内置 AI 智能体节点；fair-code 许可，自用免费

→ 告警分级、周报汇总、订单邮件解析这类跨服务的胶水逻辑，写在 HA 自动化里太别扭，它是做这种事最顺手的工具

n8n 是柏林公司 n8n GmbH 从 2019 年做起的工作流自动化平台，198.3k 星，2025 年之后因为 AI 智能体节点的加入星数暴涨。它解决的问题是：把不同服务串起来的胶水逻辑，以前要么写脚本要么用 Zapier 这类云服务；n8n 让你在自己的机器上拖节点完成。

它的核心是画布上的节点图：触发节点决定何时开始，可以是定时、Webhook、收到邮件或某个服务的事件；后续节点每个做一件事，HTTP 请求、条件判断、数据变换、发通知、写数据库，四百多种集成节点覆盖常见服务，不够就用 Code 节点写 JavaScript。AI 部分把大模型、工具、记忆做成节点，能接 Ollama 这样的本地模型。它是 fair-code 许可，自用免费，Docker 一个容器就跑。

官方模板库有几千个工作流可以直接导入；文档是英文，中文教程和视频已经很多。

在 0804 里它是延伸，做服务层的胶水。Uptime Kuma 和 Beszel 的告警都发到 n8n 的一个 Webhook，由它按严重程度分派：传感器掉线只写日志并在 HA 里亮一个黄点，NAS 盘温超阈值立刻推手机，连续三次才推的去抖规则也在这里配。每周日晚上一条定时工作流把 Beszel 的温度曲线、restic 的备份结果、Syncthing 的同步状态汇总成一份周报发到手机。电商平台的订单邮件由它解析出品牌型号和金额，写进 0801 的物品总表。
