暖村木屋 · 模块 0105 · PSK 工作台

保姆级！床下 2.6 米长的生存盒组装台，每一件小物件都有自己的坑位

一张台子上摆开 27 个小格子，把一只生存盒从零件变成成品只要 40 分钟。

📐 它在哪、有多大

在木屋东端，沿南墙东段摆一张 260×70 的写字台，东头塞进东墙梯子床的床板（1850）底下，旁边就是床下通向地堡的暗门（净高 1800）；西头距西南角炉区 400。

🎬 沉浸式想象

晚上九点，木屋只开写字台上方那盏长条灯。台面是 5cm 厚的白蜡木，2.6 米长，贴着南墙东段一路伸到梯子床的床板底下，我自己刨平上油的。台面靠里那一侧是一排 27 个小木格，每格一种物件，火石、鱼线、别针、消毒片，都是几十个一格。中间是一块 A3 大小的皮革垫，上面摊开一只空盒身。左手边是台钻和小型压合机，右手边是那把用了六年的镊子。你坐在高脚凳上，左手拿盒身，右手从左到右一格一格拿，27 件依次放进毛毡槽，动作像在做寿司。40 分钟后，盖子合上，咔哒一声，一只 PSK 出生了。头顶那台小摄像头把整个过程拍了下来，明天剪成一条视频发出去。

✅ 设想方案清单

  1. 台面 5cm 白蜡木拼板 260×70cm，沿南墙东段摆，东端伸进梯子床床板（1850）下面，四条腿用 8cm 方钢，台面高 92cm 配高脚凳
  2. 台面靠里一排 27 格小木盒零件柜，每格 8×8cm，格口贴激光刻的物件名和数量，不挡南窗
  3. 台面中间铺 A3 植鞣皮垫，装配区就是这一块，其他地方不放东西
  4. 左侧固定小型台钻和手动压合机，右侧一块磁吸工具板挂镊子、剪刀、小锉
  5. 台面上方 1.2m 长条灯 4000K 显色指数 95 以上，看毛毡颜色不偏；床板下那段另加一条小灯带
  6. 台面上方吊一台 reCamera，接 HomeAssistant 一键开始录制组装过程
  7. 台面下两层抽屉，一层放空盒身，一层放做好未贴标的成品

⚠️ 避坑提醒

  • 台面别用松木，太软，放一个月就全是压痕，白蜡木或榉木起步
  • 零件格别做太深，8cm 以上手伸进去拿最后几个小物件很难受
  • 长条灯别装在正头顶，装在靠前 20cm 的位置手才不会挡光；床板底下那 90cm 记得再补一条灯带

Seeed-Studio/OSHW-reCamera-Series ★ 474 有中文文档

Seeed 开源 AI 相机整机 reCamera 的硬件仓库：RISC-V 1TOPS SoC、可换的传感器板与底板，出厂固件自带 Node-RED 和 SenseCraft

→ 0805 把全屋 DIY 器件基准定在 Seeed 生态，摄像头就用它；台面上方那只俯拍机位换成 reCamera 整机，本机出 RTSP 给 Frigate

reCamera 是矽递科技做的开源 AI 相机整机，这个仓库放的是它的硬件：核心板、传感器板、底板的原理图、PCB 和结构件图纸全部开源。它要解决的问题是——市面上的网络摄像头要么封闭要么只会推流，想在机身上跑一点识别就得另外挂一台主机。

做法是把一台相机拆成可换的三层。核心板用 SG2002 这类 RISC-V 芯片，带 1TOPS NPU，跑的是完整 Linux；传感器板按需要换 OV5647 或者 IMX335 等不同镜头；底板决定接口，有以太网、Wi-Fi 和树莓派兼容排针几种。整机比火柴盒大不了多少，出厂固件带 Node-RED 和 SenseCraft，拖几个节点就能把检测到某类物体接到 MQTT 上，也能直接吐一路 RTSP。

官方 Wiki 有完整中文版，型号页、烧录和 Node-RED 教程都有中文，社区里换镜头、做外壳、接 Home Assistant 的例子不少，仓库本身随新型号持续更新。

放进 PSK 工作台，它就是横梁上那只俯拍机位：选带以太网底板的型号，球头座固定，正对台面中央那块 A3 皮垫，网线走横梁线槽不走 Wi-Fi。RTSP 流照旧交给 Frigate 按盒号录制，机身上另外跑一个轻量模型判断盒盖有没有合上，给磁簧开关做第二路兜底。坑是长条灯就在前方 20cm，镜头容易过曝，装好先锁曝光再调白平衡。

blakeblackshear/frigate ★ 35.1k 官方中文 README

本地实时目标检测的开源 NVR，IP 摄像头 24 小时录像、按事件保留，和 HomeAssistant 深度集成，有中文 README

→ 工作台头顶那颗摄像头接它：HA 一键触发手动事件开始录组装过程，录完落 NAS，视频直接拿去剪

Frigate 是美国开发者 Blake Blackshear 从 2019 年起维护的开源网络录像机，35.1k 星，几乎每月发版。它解决的是：家里的 IP 摄像头想本地录像和识别目标，不把画面传到云上，还要能和 Home Assistant 联动。

架构是一个 Docker 容器：用 go2rtc 从摄像头拉 RTSP 流，先做低成本的运动检测，只把有动静的区域送进 OpenCV 加 TensorFlow 的目标检测，识别出人、车、猫狗等对象后生成事件，录像按事件或全天保留在本地硬盘。检测可以跑在 Coral TPU、核显或 CPU 上；对外有 MQTT、REST API 和 WebRTC 直播，HA 集成把每路摄像头、每类对象、录像片段都变成实体，还能用 API 手动创建一个事件强制录像。

README 有官方简体中文版，文档站也有中文翻译，B 站教程很多。

放进 0105，头顶那台摄像头走 PoE 接木屋交换机，Frigate 跑在 NAS 上；写字台边一个实体按钮接 HA，按下后 HA 调 Frigate 的手动事件 API 开始录制并标记为组装，再按一下结束，片段自动保留 30 天并在 HA 面板里列出；平时它也顺便当木屋监控。坑在 4000K 长条灯直射时画面会过曝，摄像头曝光要锁定，别用自动。

inventree/InvenTree ★ 7.3k 界面有中文

开源库存与零件管理系统，BOM、库存、供应商、标签打印、REST API 和插件一应俱全，界面有简体中文

→ 27 格零件柜的账本：一只 PSK 就是一张 27 行的 BOM，每做一只自动扣库存，低于阈值 HA 点亮那一格的提醒灯

InvenTree 是澳大利亚开发者 Oliver Walters 从 2017 年起维护的开源库存管理系统，7.3k 星，2026 年 7 月发布 1.4 版，本来是给电子爱好者管元件抽屉的，后来长成了小工厂也在用的物料系统。它解决的是：几百种小零件分格存放，哪格快用完、做一批要备多少料，靠眼睛看不过来。

架构是 Django 后端加 React 前端，Docker 一行命令装好，数据库可以用 SQLite 到 PostgreSQL。核心对象是零件、库存项、存放位置和 BOM：零件定义参数和供应商，库存项挂在某个位置上有数量，BOM 描述一件产品由哪些零件按多少数量组成；建一个生产工单时它会核对库存够不够、完成时自动扣减。它自带标签模板，能给每个格子打印带二维码的标签，扫码直接进那格的库存页；REST API 完整，还有 Python 客户端和插件系统。

界面通过 Crowdin 翻译，简体中文完整，文档是英文。

放进 0105，把 PSK 建成一个装配零件，BOM 就是 27 行，27 个小木格各建一个存放位置，格口标签由它生成后激光刻；每做完一只盒子就完成一张工单扣一次库存，某格数量低于 20 时它的低库存接口被 HA 每小时轮询一次，HA 点亮那一格上方的小灯提醒补货。坑在初始盘点最累，一定要一次把 27 格数准，之后才轻松。

kennetek/gridfinity-rebuilt-openscad ★ 2.2k 无中文

Gridfinity 模块化收纳盒的 OpenSCAD 参数化重制版，尺寸分格随便改，导出 STL 直接打印

→ 27 格零件柜的内胆：格子先按 42mm 网格打印内盒试尺寸，定稿后再照着做木格，两层抽屉里的空盒身托盘也用它

Gridfinity Rebuilt 是开发者 kennetek 在 2022 年用 OpenSCAD 重写的 Gridfinity 参数化库，2.2k 星，2025 年仍在合并贡献。Gridfinity 是 YouTuber Zack Freedman 提出的 42 毫米网格收纳标准，底板和小盒按网格咬合，这个仓库把原本要在 Fusion 里改的模型变成几行参数就能生成的代码，想要尺寸正好的分格盒不必从零建模。

工作原理是 OpenSCAD 脚本：你在顶部改几个数字，几格宽、几格长、多高、内部沿 X 和 Y 各分几格，要不要挖手指槽、标签翻边、磁铁孔和堆叠唇边，点渲染就得到一个 STL。底部网格脚是标准的，能扣进任何 Gridfinity 底板；仓库还提供底板、花瓶模式薄壁盒等变体，打印不需要支撑，也能命令行批量出图。

Printables 上按它生成的盒子成千上万；文档是英文，B 站有不少 Gridfinity 收纳的中文视频。

放进 0105，27 格零件柜先用它出 27 只 1 乘 1 或 1 乘 2 的小盒，每格按物件大小试装两周，确认哪格该更宽、哪格该加手指槽，再照着最终尺寸做 8 乘 8 厘米的木格；台面下两层抽屉铺一块 Gridfinity 底板，空盒身和成品各用一个定制托盘固定，拉抽屉不晃。坑在 OpenSCAD 渲染慢，装开发版快得多。

frappe/erpnext ★ 38.6k 界面有中文 延伸

Frappe 框架上的开源 ERP：物料清单 BOM、工单、库存、采购、销售、财务全流程，制造业小厂常用

→ PSK 是 27 件物件组成的真产品，做多了就需要 BOM 和工单：一只盒子消耗哪些零件、哪格快空了该补货，ERPNext 是这套逻辑的教科书

ERPNext 是印度 Frappe 公司做的开源 ERP，Python 后端加 Frappe 框架，38.6k 星，是开源 ERP 里社区最大的一个。它要解决的问题是：小工厂和小品牌需要 SAP 那套物料、生产、库存、财务的逻辑，但付不起也用不了那么重的东西。

它的核心是 Frappe 框架的 DocType：每种业务对象（物料、BOM、工单、采购单）都是一张有字段、有工作流、有权限的表，界面和报表自动生成。制造模块的流程是：先给成品建物料清单 BOM，列出每一件子物料和数量；下工单时系统按 BOM 算出要领多少料、缺什么；完工后成品入库、原料扣减，库存低于安全线自动生成采购建议。它还带 CRM、项目、人事和会计，一套 Docker 就能跑。

生态方面它有中文界面翻译，国内有做实施的公司和不少中文文档；2025 年后每年一个大版本，v15 是当前主线。

放到 0105 里它是延伸的思路来源，不一定全上：工作台那排 27 格零件柜就是一张 BOM 的物理形态，每格贴的数量标签就是库存。在 ERPNext 里给 PSK 建一个 BOM，27 行子物料加毛毡和盒身，每组装一只就下一张工单，库存自动减；把每格的安全库存设成 20，低于就进采购建议，周末统一下单。注意它对一个人的作坊来说太重，只用物料、BOM、库存三个模块，别去碰会计；觉得重的话，0105 原有的 InvenTree 是更轻的选择。

Part-DB/Part-DB-server ★ 1.7k 界面有中文 延伸

给电子元件和小零件做的开源库存系统：存放位置树、参数、供应商价格、条码标签打印，支持从立创和 Mouser 拉数据

→ 工作台那 27 格小零件加上抽屉里的电子小件，需要一个知道每样东西在哪一格、还剩几个的轻量库存，Part-DB 就是为这种小格子生的

Part-DB 是德国开发者 Jan Böhmer 用 PHP Symfony 重写的开源零件库存系统，1.7k 星，起初是给电子爱好者管电阻电容的，后来变成了通用的小零件库存。它要解决的问题是：抽屉和小格子里几百种零件，谁也记不住哪个在哪、还剩多少、上次从哪买的。

它的数据模型是零件加存放位置树加类别树：每个零件有名称、参数、图片、附件、最小库存和多个库存条目，每条库存指向一个位置（房间→柜子→抽屉→格子）；供应商信息记录订单号和价格阶梯，信息提供者功能可以直接从立创商城、Mouser、DigiKey 等拉回参数和图片。它能生成带二维码或条码的标签用标签机打印，扫码就跳到那件零件的页面；还有项目 BOM 功能，能算一个项目需要的零件够不够。部署是 Docker 一行，浏览器访问，手机也能用。

社区方面它是小而稳定的项目，2025 年后仍在更新，界面翻译里有简体中文，中文教程主要在电子 DIY 圈。

放到 0105 里它是延伸里最贴身的一个：27 格零件柜每格建一个位置，每格一种物件登记数量；格口那张激光刻的标签旁再贴一个 Part-DB 生成的小二维码，手机扫一下就减库存或看供应商链接。工作台抽屉里的电子小件、0106 炉子的传感器备件、0803 鸭子的备用舵机也全部归进来，统一用它的位置树。它比 ERPNext 轻得多，一个人用刚好；和 0105 已有的 InvenTree 是同类，选一个用就行，Part-DB 的优点是标签打印和立创拉数据更顺手。
