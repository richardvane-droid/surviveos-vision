暖村木屋 · 模块 0107 · 小吧台

一整个爱住！木屋北墙 2.5 米矮吧台，磨完豆子对着画框墙发呆

一条老榆木台面的矮柜加一把凳子，看完生存盒，坐下来喝到炉火熄灭。

⬜ 真实项目待设计 #小吧台#原木风#精神角落#热红酒#一人食

📐 它在哪、有多大

在木屋北墙西段，从西墙起 ≈2.5m 长的设备带：矮柜高 900、台面电器顶不超过 1500，上方墙面留给 0103/0104；台面东头放 0205 生态鱼缸，右手再过去是 0101 挂墙展台，身后 2 米就是西南角炉区。

🎬 沉浸式想象

看完挂墙展台、看完那面九宫格，最后总会走到北墙西段这条吧台坐下。台面是一整块 2.5 米的老榆木，边缘不切直，留着树皮的弧线，下面是 90 公分高的松木矮柜。台面上从西到东排着管线热水机、制冰机、一台复古铜色的磨豆机加手冲架，最东头是那只生态鱼缸，鱼在台面上游。柜门里面三层木架，上面是十几个不同的杯子和一排玻璃罐，装着咖啡豆、桂花、陈皮、干柠檬片。台面一角一口小铸铁锅，冬天里面煨着一杯热红酒。一把矮凳，坐垫是旧帆布。梁底三盏黄铜小射灯，只照亮台面这一块，抬头就是画框墙今天换的画。你坐下，手肘搁在榆木上，台面是温的，因为柴火炉就在两米外。磨完豆子，问自己一句：手冲还是热红酒？

✅ 设想方案清单

  1. 台面用一整块 2.5m 老榆木自然边板，厚 6cm，一侧留树皮弧线不切直，压在 90cm 高的松木矮柜上
  2. 矮柜高 90cm 深 45cm，配一把 65cm 矮凳，凳面用旧帆布包一层薄海绵
  3. 柜门里三层木架，放杯子和 8 个玻璃罐，罐上贴手写牛皮纸标签，台面上永远只留电器
  4. 台面从西到东：管线热水机、制冰机、磨豆机加手冲架、电陶炉小铸铁锅，最东头 0205 生态鱼缸，电器顶不超过 1.5m
  5. 梁底三盏黄铜小射灯 2700K 朝下打台面，接 HomeAssistant 做自己坐下自动调暗到 30%，不遮上方画框墙
  6. 矮柜侧面钉一个小铜钩挂开瓶器，柜里留一格放小冰箱和几瓶本地黄酒
  7. 台面上永远放一只 PSK 生存盒当装饰，边喝边翻，这是给自己的每日种草环节

🔥 小红书灵感点

  • 小红书家庭吧台风：自然边榆木台面加黄铜小灯是热门组合，低成本高质感
  • 精神角落：这是木屋里唯一没有工作属性的地方，坐下就是休息
  • 去家务化：台面上只留手冲和热红酒两套东西，别的都收进柜子，收拾只要三分钟

⚠️ 避坑提醒

  • 自然边榆木一定要做好封闭，不然树皮那一侧一年就掉渣
  • 吧台别做成 105 高的高吧，木屋北墙上面还要挂三面展示墙，90 高矮柜才留得出墙面
  • 别在台面上方吊灯，吊灯会挡住画框墙，灯装梁底朝下打就够了

grocy/grocy ★ 9.5k 界面有中文

自称“冰箱之外的 ERP”：自托管的家庭食材与日用品管理，管库存、保质期、购物清单和消耗记录

→ 小冰箱和矮柜的账本：咖啡豆开袋日期、黄酒还剩几瓶、桂花陈皮什么时候过期，罐上扫码入库消耗，过期前推提醒

Grocy 是德国开发者 Bernd Bestel 从 2017 年起维护的自托管家庭管理系统，9.5k 星。它解决的问题被它自己一句话概括为“冰箱之外的 ERP”：家里买的吃的用的，什么时候买的、放在哪、还剩多少、什么时候过期，靠脑子记总会重复买或放坏。

工作原理是一套小型进销存：每样东西建一个产品，定义单位、默认保质期和存放位置，买回来就入库，用掉就消耗，可以扫商品条码或自己打的二维码，手机在柜前扫一下就完成。系统按先进先出记每一批的到期日，快过期的自动进首页提醒，低于最低库存自动进购物清单。后端是 PHP 加 SQLite，Docker 一条命令起来。

生态上它有官方的 HomeAssistant 集成和条码前端 Barcode Buddy，社区很大。翻译走 Transifex，简体中文界面是完整的。

放进 0107 里它管矮柜和小冰箱这一层：咖啡豆按袋建产品记开袋日期，桂花、陈皮、干柠檬片按罐记到期，黄酒按瓶数记，每只玻璃罐的牛皮纸标签角上加一个小二维码，补料和用掉都是扫一下。HA 集成把快过期和需要购买两条读出来，周末出门前推一次。它和 Bar Assistant 的分工是：Grocy 管东西还在不在、坏没坏，Bar Assistant 管今晚拿它们做什么。

karlomikus/bar-assistant ★ 1.0k 无中文

自托管家庭吧台管理系统，管酒水库存、500 多个鸡尾酒配方和购物清单，带 REST API

→ 柜里 8 只玻璃罐和几瓶黄酒都登记进去，坐下翻平板按库存反查今晚能做什么，缺料自动进购物清单推手机

Bar Assistant 是克罗地亚开发者 Karlo Mikuš 从 2022 年起做的自托管家庭吧台管理系统，1.0k 星。它解决的问题很具体：家里的酒、糖浆、干料到底还剩多少，用手头这些东西今晚能调出什么，缺什么该买什么。

架构是前后端分离：后端 bar-assistant 是 PHP 写的 API 服务，负责配方、原料、库存、购物清单和用户权限；前端 Salt Rim 是一个 Vue 单页应用，手机上可以装成 PWA。数据流是先把原料建档、勾上在库，配方库里 500 多款鸡尾酒会按库存自动分成现在能做和还差一样；做了一杯就按配方扣减，任何原料低于设定量自动进购物清单。配方可以从网址、JSON、YAML 导入，也能算成本、按人数放大。

生态上它 Docker 一条命令起来，Discord 社区活跃，翻译走 Crowdin 但没有中文界面。

放进 0107 里它就是吧台点单账本：柜里 8 只玻璃罐的咖啡豆、桂花、陈皮、干柠檬片和几瓶本地黄酒各建一条原料，热红酒、桂花黄酒、陈皮茶写成自定义配方，坐下翻平板按库存筛可做的那几款。HA 用它的 REST API 每晚读一次库存，低于 1 份用量就推手机。坑是它默认是鸡尾酒思维，原料单位要自己改成 g 和 ml，别按盎司算。

beeb/coffee-scale-app ★ 146 无中文

DIY 蓝牙咖啡秤：ESP32 + HX711 称重传感器跑 Rust 固件，配一个手机 PWA 显示重量、计时和萃取曲线

→ 手冲架下那台秤自己做：磨豆注水计时、流速曲线全在手机网页上，每天一杯的种草环节多了一条能对比的曲线

coffee-scale-app 是瑞士开发者 beeb 做的开源 DIY 咖啡秤，146 星，从 2021 年做到现在，2026 年 9 月还在发新版。它解决的问题是：市面上带蓝牙、能画曲线的咖啡秤要一千多块，而一块 ESP32、一颗 HX711 称重模块、一个小 OLED 加一节锂电池，成本不到一百块就能做出同样的事。

工作原理分两半：秤本身跑 Rust 写的固件，用 esp-rs 生态，HX711 高频采样后经卡尔曼滤波去抖，128×32 的 OLED 上显示重量，通过低功耗蓝牙广播出去；另一半是一个网页 PWA，手机浏览器打开 coffee.beeb.li 或自己部署的一份，连上秤后实时显示重量、计时、预浸时间，并把这次注水的重量曲线和一条参考萃取曲线叠在一起。外壳有 3D 打印件，去 Printables 下载。

生态上它是 ESP32 咖啡秤里最完整的一个，README 详细但只有英文，好在接线就四根。

放进 0107 里它就是手冲架下那台秤：磨完豆按一下归零，注水时手机放在榆木台面上看曲线，粉水比和流速有了记录。用 ESP32-C3 把体积再缩小一圈，外壳改成一只小胡桃木盒，秤盘留着防水。坑是 HX711 受温度影响，台面离炉子只有两米，每次开始前先归零，别把秤放在电陶炉旁边。

mealie-recipes/mealie ★ 13.1k 界面有中文 延伸

自托管菜谱管理与餐食计划：一键从网址抓菜谱、按份数换算、周计划、购物清单、多用户，FastAPI + Nuxt

→ 吧台上手冲、热红酒、桂花陈皮茶这些配方要有个地方记，Mealie 抓网址一键存、按杯数换算最省事，还能连 HomeAssistant

Mealie 是 Hayden Kotelniski 发起的自托管菜谱管理器，Python FastAPI 后端加 Nuxt 前端，13.1k 星，是自托管菜谱工具里最常被推荐的一个。它要解决的问题是：菜谱散在收藏夹、截图和微信聊天记录里，做的时候找不到，份量也不对。

它的核心功能是菜谱抓取：把任何食谱网页的网址粘进去，它解析页面里的结构化数据自动填好配料、步骤、时间、图片，抓不到的也能手动录或者传照片让 OpenAI 识别。菜谱可以打标签、分类、按份数自动换算用量，拖进周计划里就生成一周的餐单，再一键生成购物清单，配料自动合并同类项。多用户和家庭组适合一家人用，界面响应式，手机加到主屏幕当 App 用。它有完整的 REST API，HomeAssistant 有社区集成能把今天的餐单显示在仪表盘上。

生态方面 2025 年后仍是几周一个版本，界面翻译覆盖 35 种以上语言含简体中文，中文部署教程在 NAS 圈很多。

放到 0107 里它是延伸项目，管的不是饭而是吧台：手冲咖啡按豆子记参数（粉水比、水温、时间），热红酒、桂花陈皮茶、干柠檬片气泡水各一条配方，按一杯或两杯自动换算；柜门里那 8 个玻璃罐的内容物做成配料，购物清单就是下次去镇上补货的清单。HomeAssistant 集成让 0802 大屏在下午三点弹一句今天的推荐饮品。注意它抓中文菜谱网站的成功率一般，吧台这些配方基本要自己录，好在总共也就二十来条。

TandoorRecipes/recipes ★ 8.6k 界面有中文 延伸

Django 写的自托管菜谱与餐食计划：菜谱抓取、步骤化编辑、餐食计划、购物清单、空间隔离和食材库存管理

→ 和 Mealie 是同一赛道的另一条路线，多了配料库存和保质期管理，正好把吧台玻璃罐和 0106 炉顶那口锅的食材也管起来

Tandoor Recipes 是德国开发者 vabene1111 用 Django 加 Vue 做的自托管菜谱管理器，8.6k 星，和 Mealie 并列自托管菜谱的两大选择。它要解决的问题和 Mealie 一样：菜谱要集中、要能计划、要能变成购物清单，但它的取向更偏结构化和数据。

它的菜谱模型是分步骤的，每一步有自己的配料和时长，做的时候有一个逐步模式按步走、计时器直接开；配料是一个有层级和别名的食材库，同一种东西不同叫法能合并。餐食计划按周排，购物清单可以按超市货架分类排序，还能多人实时共享勾选。特色是空间的概念：一个实例可以开多个互相隔离的空间给不同家庭。它有食材库存与保质期的实验功能，能从 Nextcloud、Paprika、Mealie 等格式批量导入，REST API 完整，也有 HomeAssistant 社区集成。部署走 Docker Compose，官方给了十几种反向代理组合的示例。

生态方面 2025 年后仍在活跃开发，界面翻译含简体中文，中文教程主要在 NAS 和自托管社区。

放到 0107 里它是延伸里和 Mealie 二选一的另一半：如果想把吧台管得更细——热红酒配方分成煮香料和加酒两步各自计时、陈皮桂花按克数进食材库、每个玻璃罐登记装罐日期和保质期——Tandoor 的结构更合适。它还能顺手把 0106 炉顶烤红薯、炖汤这类炉边菜也收进来，用空间把吧台饮品和炉边菜分开。注意两个别都装，都装了配方会分家；先各试一周，留一个。
