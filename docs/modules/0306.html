被问爆了！屋顶一根杆子，让我比天气预报早半小时知道下雨

🎬 沉浸式想象

早上六点半，天窗外那根 1.5 米的铝杆上，小风杯转得飞快，风向标指着东南。隔断上的小墨水屏显示：气温 24.3 度，湿度 82%，气压在往下掉。你看了一眼，知道中午前要下雨。HomeAssistant 已经自动帮草地的浇灌系统按了暂停，还顺手把帐篷区的天窗帘关上了。你端着咖啡站在天窗边，看着风杯转，突然觉得这根杆子比手机里的天气 APP 更像一个真实的朋友。远处山上的云压下来，雨量筒里还是空的，但你已经收好了晾在庭院的睡袋。

✅ 设想方案清单

  1. 天窗旁边伸出一根 1.5 米铝合金杆，顶端装风杯、风向标、雨量筒三件套
  2. 杆子中段装 Grove 温湿度 + 气压模块的百叶盒，避免太阳直晒
  3. 所有传感器接一块 XIAO ESP32C6 跑 ESPHome，数据直接进 HomeAssistant
  4. 阁楼间东侧隔断上装一块 7.5 寸墨水屏，显示当前天气 + 过去 24 小时曲线
  5. 气压下降 + 湿度上升 → 自动暂停 0602 草地浇灌，并推送“收衣服”提醒
  6. 杆子底部做一个可以放倒的铰链，台风天从天窗伸手就能放倒
  7. 每年数据存进 0802 中枢，做一张“我家的一年气候图”

Seeed-Studio/OSHW-XIAO-Series ★ 81 无中文

XIAO 全系列开源硬件资料：ESP32C3/C5/C6/S3、nRF52840、RP2040/2350、MG24 的引脚图、原理图与参考设计

→ 0805 定下全屋主控走 XIAO，这里是官方一手硬件资料；0306 气象杆下那块采集板和墨水屏驱动板都照它的引脚图画，选 ESP32C6 兼顾 Wi-Fi 与低功耗

XIAO 是矽递科技（Seeed Studio）做了五年的拇指大小主控系列，21×17mm 的板子上集成 USB-C、锂电充电、深度睡眠和板载天线，同一副引脚下并排放着 ESP32C3 / C5 / C6 / S3、nRF52840、RP2040 / RP2350、MG24 等十几种芯片。这个仓库是这一系列的开源硬件资料本体。

目录按型号分，每个型号给出引脚定义图、原理图 PDF、机械尺寸和参考设计，外加扩展底板与电池板图纸。它真正的用处是布板前的那几个决定：哪几个脚能做 ADC、哪几个脚睡眠时会漏电、外接天线走哪个座子、太阳能小板怎么接充电管理，这些都写在资料里，不用拆板子量。

仓库 81 星、无中文，但它是 0805 定标器件的官方一手资料，这个需求没有第二个现成答案；中文内容在 Seeed Wiki 的 cn 站上按型号对应，ESPHome 已原生支持 XIAO 全系。

在 0306 里它管两块板：气象杆底部的采集板选 XIAO ESP32C6，照资料里的 ADC 与中断脚接风速风向和雨量筒的翻斗干簧管，百叶盒里那颗 Grove 气压温湿度模块走 I2C；隔断上的墨水屏用另一块 XIAO ESP32C6 驱动，靠深度睡眠一天刷几十次。注意户外那块要引外置天线，别让金属杆挡住信号。

Madelena/esphome-weatherman-dashboard ★ 1.3k 无中文

用 ESP32 驱动 7.5 寸墨水屏显示天气和预报的 ESPHome 配置，字体图标全打包

→ 阁楼墙上那块 7.5 寸墨水屏照它做，把气象站的温湿压和 24 小时曲线画上去，极简出片

Weatherman 是纽约设计师 Madelena 做的一块墨水屏天气面板，1.3k 星，是 ESPHome 社区里被复刻最多的电子墨水屏项目之一。它的初衷是出门前扫一眼天气和地铁，又不想再多一块发光的屏幕，于是把 7.5 寸墨水屏装进宜家 RIBBA 相框挂在门口。

它的原理不复杂：Waveshare 7.5 寸 800×480 墨水屏接在 Waveshare 的 ESP32 驱动板上，ESP32 跑 ESPHome；所有数据都不在板子上算，而是由 Home Assistant 用模板传感器把天气预报、温度、地铁到站整理好，ESPHome 通过原生 API 把这些实体取过来，用自带的绘图指令画字、画图标，然后整屏刷新。仓库把字体、天气图标、布局 YAML 全部打包好了，附带 HA 那一侧的模板配置；为了延长墨水屏寿命，还用动作传感器控制刷新频率。

仓库两年没大改，但 ESPHome 的墨水屏组件一直在维护，中文只有 B 站上的复刻视频。

在 0306 里，隔断上那块 7.5 寸屏照它做：去掉地铁部分，换成气象杆的实时温湿压、风速风向、雨量，以及 HA 历史数据画出来的 24 小时气压曲线；曲线要自己用 ESPHome 的 line 指令逐点画。坑是中文字体：需要在 YAML 里引入一份思源黑体子集，否则汉字显示成方块，字体文件太大会编译不过，只保留用到的字。

hugokernel/esphome-weather-station ★ 338 无中文

Elektor 气象站的 ESPHome 版本，风速、风向、翻斗雨量、温湿压、光照全套配置

→ 风杯、风向标、雨量筒三件套的引脚和换算公式都写好了，抄它的 YAML 改改就能进 HA

esphome-weather-station 是法国开发者 hugokernel 把 Elektor 杂志的气象站方案改写成 ESPHome 版本的项目，338 星，是 ESPHome 社区里最完整的一套户外气象站配置。它解决的问题是：市面上那种风杯、风向标、翻斗雨量筒三件套只给几根线，怎么换算成风速、风向角和毫米降雨量，得自己一个个查。

它把这些都写进了一份 YAML：风速用脉冲计数器组件数干簧管每秒闭合次数再乘系数；风向标内部是八个方位的磁簧开关接不同电阻，用 ADC 读电压后按分段表映射成十六个方向；雨量筒每翻一次斗计一个脉冲，乘每斗毫米数得到降雨量，再按小时和天累加；温湿气压走 BME280，光照走 TSL2561，太阳能板功率用 INA219 读。所有传感器接一块 ESP32，通过 ESPHome 原生 API 进 Home Assistant，仓库还附了 3D 打印支架和法语说明。

它对应的硬件是很常见的 WH-SP-WS02 三件套，国内电商上同款几十块，引脚定义一样。

在 0306 里，杆顶三件套和百叶盒里的 BME280 都接一块 ESP32，YAML 基本照抄，只改引脚和风速系数；供电走 0304 的储能而不是它的太阳能板。要注意风向标的电阻分段表要按自己买的那只实测校准一遍，ADC 用衰减 11dB 才读得到全量程。

3KUdelta/Solar_WiFi_Weather_Station ★ 117 无中文

太阳能供电的 ESP 气象站，用气压变化趋势跑 Zambretti 算法本地预报天气

→ “比天气预报早半小时知道下雨”靠的就是气压趋势，把它的 Zambretti 算法搬到 HA 自动化里；GitHub 上这个算法没有更知名的完整实现，所以保留这个小项目

Solar_WiFi_Weather_Station 是德国爱好者 3KUdelta 在 Open Green Energy 项目基础上做的太阳能 WiFi 气象站，117 星，它最有价值的部分不是硬件，而是把老式的 Zambretti 天气预报算法完整搬进了 ESP8266 固件里，是 GitHub 上关于这个算法最常被引用的实现。Zambretti 预报器本是 1915 年的一只黄铜转盘，只用气压值、气压趋势和季节三个输入就能给出二十六种结论，本地气压比网络预报更贴近自家屋顶。

它的流程是：BME280 每十分钟测一次气压，先按海拔换算成海平面气压，然后和一到三小时前的读数比较得到趋势（上升、稳定、下降），再把当前气压落到 Zambretti 的分段表里，查出预报编号并翻译成一句话；固件顺带按室外温度做了冬夏调整，冷天把雨改成雪。历史读数存在闪存里，结果推到 Blynk 或 Thingspeak。

项目几年没更新，硬件部分可以不看，README 里的算法说明和翻译表是精华，中文资料只有零散的博客。

在 0306 里，不刷它的固件，而是把 Zambretti 的查表逻辑用 Home Assistant 的模板传感器重写：输入是气象杆的气压和三小时前的历史值，输出一个预报实体；预报转向雨且湿度上升时暂停 0602 浇灌并推送收衣服。坑是气压必须先换算到海平面，否则山上永远显示暴风。

weewx/weewx ★ 1.2k 无中文 延伸

Python 写的开源气象站软件：驱动几十种商用气象站，存数据库、生成网页报表、上传到 Weather Underground 等网络

→ 自制气象站的数据除了进 HA，还需要一套按气象行业规矩做日报、月报和年度气候图的软件，weewx 是这方面二十年的标杆

WeeWX 是 Tom Keffer 从 2009 年起维护的开源气象站软件，用 Python 写成，1.2k 星，八千多次提交，2026 年 6 月发布 5.4 版。它要解决的问题是：气象站硬件只会吐原始数据，但一个像样的气象站需要归档、统计、报表、网页和向公共气象网络上传，这些都是它做的。

它的工作方式是驱动加引擎加报表：驱动层对接几十种商用气象站（Davis、Fine Offset、Ecowitt 等），也能通过 MQTT 驱动接收任意自制站的数据；引擎按固定间隔把数据写进 SQLite 或 MySQL 归档表，同时算出日、周、月、年的最高最低和累计值；报表层用 Cheetah 模板生成静态网页和图表，默认皮肤开箱就能看，也能上传到 Weather Underground、CWOP 等网络。扩展机制允许加驱动、加服务、加皮肤，社区有上百个扩展。

生态上它的文档非常详尽，用户论坛活跃，树莓派上跑十几年不倒是常态；文档只有英文，中文资料不多，但配置就是一个文本文件，看着示例改并不难。

对 0306 来说它是延伸项目：铝杆上的三件套和百叶盒数据经 ESPHome 进 HomeAssistant 负责实时和联动，而年度那张我家的一年气候图交给 WeeWX 更专业。在 0802 服务器上跑一份，用 MQTT 驱动订阅 HA 转发的主题收温湿度、气压、风速风向和雨量，按气象站的规矩算日雨量、阵风和露点，自动生成网页报表，年底导出全年温度和降水曲线，比自己在 HA 里拼图表省事得多。

merbanan/rtl_433 ★ 7.6k 无中文 延伸

用几十块钱的 RTL-SDR 电视棒解码 433/868/915MHz 无线传感器：温湿度、雨量、风速、TPMS 等两百多种协议，输出 JSON 或 MQTT

→ 自制气象站之外，邻居和商用气象站的 433MHz 探头都在空中飞，rtl_433 一根电视棒就能全收进 HA，是气象站的免费外挂探头

rtl_433 是 Benjamin Larsson 发起、社区维护的软件无线电解码工具，用 C 写成，7.6k 星，是 SDR 玩家和智能家居圈里最常用的 433MHz 解码器。它要解决的问题是：无数无线温湿度计、雨量计、风速计、门磁都在 ISM 频段用私有协议广播，买家只能用厂家的显示屏看，rtl_433 把它们统统解出来。

它的工作方式是接收、解调、匹配：一根二三十块的 RTL-SDR 电视棒接在树莓派或电脑上，rtl_433 把指定频率的射频信号采样下来，做 OOK 或 FSK 解调，再用两百多个内置解码器逐个匹配脉冲模式，识别出是哪家哪个型号，解析出温湿度、风速、雨量、电量等字段，以 JSON 或 MQTT 输出。它有 HomeAssistant 自动发现插件，每个探头自动变成一组实体。

生态上支持列表还在增长；文档是英文，但国内 SDR 圈和 HA 论坛教程不少，有 Docker 镜像和 HA 附加组件。

对 0306 来说它是延伸项目：自制气象站建满一套探头很费事，rtl_433 让阁楼多出许多免费探头。在 0802 服务器上插一根电视棒，天线从天窗边伸出去，几十米内所有 433MHz 温湿度计、别人家的雨量筒、甚至隔壁商用气象站的数据都能进 HA，和自制站对比校准；再把几十块的无线温湿度计放进 0402 材料仓库或 0302 装备区，不布线就有了湿度报警。433MHz 是开放的低功率频段，只收不发没有合规问题。
