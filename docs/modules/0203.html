地堡 · 模块 0203 · 控温控湿

无窗地堡潮到长毛？我用一台除湿机 + 一条管道把它变成恒温洞穴

全年 22℃、湿度 55%，地堡是全屋最舒服的一间房。

🎬 沉浸式想象

梅雨季第 11 天，外面的木屋门框已经吸水发胀，你却光着脚踩在地堡的软木地板上，一点不黏。墙上那块小表盘稳稳指着 21.8℃ / 54%，除湿机藏在东侧储藏室的柜子里，只听见风管里很轻的一点气流声。你顺手摸了一下藏在墙角的书脊，干燥、有点凉。手机弹了一条 HomeAssistant 通知：今日排水 4.2L，已自动排进隔壁卫生间的下水。你想起以前住地下室时被子那股味道，然后把毯子往身上一裹，继续看片。

✅ 设想方案清单

  1. 储藏室靠卫生间隔墙的柜体里装一台 50L/天工业除湿机，冷凝水直排到 0202 的污水提升泵，不用倒桶
  2. 沿天花板走一圈 Φ100 风管，四个出风口分别对着床、沙发、书架和衣柜角落
  3. 墙面刷防潮底漆 + 软木地板，地面下铺一层防潮膜，先把“源头”堵住
  4. 布 4 个 ESPHome 温湿度探头（床头/墙角/柜内/风管出口），墙上一块小表盘实时显示
  5. 地堡没窗，新风只能从东墙靠门口高处开一个小风口（找工人穿墙）引进来，进风口加 HEPA + 活性炭
  6. 冬天用小风管式暖风机补温，夏天靠无窗厚墙和水泥地本身的凉，目标全年 20～24℃
  7. 湿度超过 65% 自动强力除湿并推送提醒，低于 45% 停机保护木制品

🔥 小红书灵感点

  • “洞穴风卧室”：无窗厚墙恒温恒湿其实是优势，把它包装成夏天的避暑洞穴
  • “数据可视化墙”：温湿度表盘用复古指针表，比液晶屏更有 workshop 氛围
  • “和植物一起住”：湿度稳定之后，地堡角落可以养蕨类和苔藓球

⚠️ 避坑提醒

  • 除湿机噪音别小看，一定藏进柜子并做隔音，不然睡觉像睡在空调外机旁
  • 冷凝水管一定要有坡度，平走两米必堵，堵了就是一地水
  • 只除湿不换气会闷，新风一定要有，CO2 探头也别省

esphome/esphome ★ 11.7k 无中文（社区教程多）

用 YAML 配置 ESP32 / ESP8266 传感器和控制器并接入 HomeAssistant 的系统，Nabu Casa 官方维护

→ 四个温湿度探头、风管出口传感器、墙上小表盘和新风机调速全靠它，是这个模块的核心依赖

ESPHome 是 2018 年由 Otto Winter 发起、现在归 Home Assistant 母公司 Nabu Casa 维护的开源项目，11.7k 星。想让一块 ESP32 读传感器、控继电器并接进家庭自动化，以前得写 Arduino 代码，现在只要一份 YAML 声明“接了一颗 SHT31、一个继电器、一块屏”，它就自动生成固件并无线刷写。

流程是在 HA 的 ESPHome 插件里写 YAML，编译，推到板子；板子用原生 API 和 HA 直连，每个传感器、开关自动变成实体。它内置了上千个组件：温湿度、CO2、PM2.5 各种传感器，PWM 风扇、步进电机、显示屏、蓝牙代理，还有 PID、阈值、定时这类本地自动化，断网时逻辑照跑。生态是 ESP 圈最大的，每月一版；官方文档英文，中文教程极多。

在 0203 里它是整套控温控湿的神经末梢：床头、墙角、柜内、风管出口四颗 SHT31 各接一块 ESP32-C3，用 YAML 里的 filters 做滑动平均再报给 HA；储藏室隔墙外那块小表盘也是一块 ESPHome 板带一块圆屏，直接画指针；新风机的 PWM 用它的 fan 组件按 CO2 分档。坑是探头要远离出风口正对处，否则读的是风管温度不是房间温度。

wuwentao/midea_ac_lan ★ 1.9k 官方中文 README

美的 M-Smart 家电的 HomeAssistant 本地局域网集成，支持空调、除湿机、风扇等 35 类设备，中文社区维护

→ 美的系工业除湿机不拆机、不走云，直接在局域网里被 HA 接管，档位、目标湿度、水箱满报警都成实体

midea_ac_lan 最早由中国开发者 georgezhao2010 写成，2023 年后由 wuwentao 接手维护，1.9k 星，是 Home Assistant 里控制美的系家电用得最广的集成，README 有简体中文，还有 QQ 群。美的及其贴牌的空调、除湿机原本都得靠美居 App 走云端，云一抽风就失联；这个集成让 HA 直接在局域网里和设备的 WiFi 模块对话，本地控制。

原理是逆向了美的 M-Smart 局域网协议：UDP 广播发现设备，用首次从美的云取到的密钥建立加密连接，之后指令和状态都在局域网内往返。它按设备类型写了几十个解析器，除湿机（A1）能读当前湿度、水箱满、滤网提醒，能设目标湿度、风速、模式和定时。

它走 HACS 安装，支持 35 种以上设备类型，2025 年后仍频繁更新，issue 区中英文混杂。

在 0203 里它接管储藏室柜子里那台 50L 工业除湿机：只要买美的或其贴牌型号且带 WiFi，不用拆机就能变成 HA 里的 humidifier 实体，再用 HA 自带的 generic_hygrostat 做 45%～65% 区间调度，超 65% 强力档并推送，低于 45% 停机护木器；排水量按提升泵启动次数换算。坑是首次配置要用美的账号取一次密钥；工业型号若不是 M-Smart 协议就不支持，买前先查支持列表。

airgradienthq/arduino ★ 377 无中文

AirGradient 开源硬件空气质量监测仪的固件与库，测 CO2、PM2.5、温湿度、TVOC，ESP8266 / ESP32-C3

→ 地堡只除湿不换气会闷，照它的选型做一台 CO2 探头，新风什么时候开就有了依据

airgradienthq/arduino 是泰国公司 AirGradient 开源的空气质量监测仪固件，377 星。AirGradient 把整套监测仪的 PCB、外壳和固件全部开源，可以买套件也可以照 BOM 自己焊，这个仓库是那台机器的大脑，也是一份“空气监测怎么选传感器”的参考。

固件跑在 ESP8266 或 ESP32-C3 上，围绕几颗公认靠谱的传感器：SenseAir S8 测 CO2，Plantower PMS5003 测 PM2.5，Sensirion SHT40 测温湿度，SGP41 测 TVOC 和 NOx。固件定周期读数、校准、滑动平均，显示在自带 OLED 上，再经本地 API 或 MQTT 交给 Home Assistant，HA 有官方集成。仓库持续更新，文档英文，ESPHome 社区也有对应 YAML。

在 0203 里它解决“闷”的问题：地堡没窗，只除湿不换气 CO2 会涨到两三千 ppm，人只觉得困。照它做一颗 SenseAir S8 探头，用 ESPHome 的 senseair 组件接到 HA，装在沙发旁墙上；HA 按 ppm 分三档驱动东墙高处那台新风机的 PWM：800 以下停、1000 以上低速、1500 以上全速并推送。坑是 S8 的自动校准假定每周有一次 400ppm 的新鲜空气，地堡里没有，得关掉自动校准，定期拿到户外手动校。

Koenkk/zigbee2mqtt ★ 15.2k 界面有中文 延伸

一根 Zigbee 适配器加一个 Node.js 服务，把三千多种 Zigbee 设备直接翻译成 MQTT，不要任何品牌网关

→ 地堡里四个温湿度探头、水浸和门窗传感器想用电池款而不是拉线，Zigbee 是最省电最成熟的无线路线，zigbee2mqtt 是它的开源入口

zigbee2mqtt 是荷兰开发者 Koen Kanters 在 2018 年发起的项目，15.2k 星，是开源智能家居里接 Zigbee 设备的事实标准。它要解决的问题是：Zigbee 传感器和灯泡便宜又省电，但每个品牌都要自家网关和 App；它用一根通用的 Zigbee USB 适配器把所有品牌的设备接到一起，再统一翻译成 MQTT。

它的架构是：Zigbee USB 适配器通过串口连到跑着 zigbee2mqtt 的机器，Node.js 服务管理网络的配对、路由和密钥；设备上报的原始 Zigbee 簇数据由庞大的设备库翻译成 JSON 发布到 MQTT 主题，反过来 MQTT 收到的指令翻译回 Zigbee 命令。它自带网页前端，能看拓扑图和信号强度；对 HomeAssistant 有 MQTT 自动发现，设备一配对就自动出现。

生态是这类项目里最大的，支持设备超过三千种，2025 年后仍是每月一个版本，前端有简体中文，中文教程极多，Aqara、涂鸦的设备基本都在列表里。

对 0203 它是延伸的无线路线：床头、墙角、柜内三个温湿度探头用电池款 Zigbee 传感器代替拉线的 ESPHome，风管出口那个高温高湿的位置仍用有线；除湿机柜的水浸传感器和门磁也一并上 Zigbee。适配器插在 0802 那台服务器上，再放两个 Zigbee 插座当路由器把信号绕过混凝土墙。注意地堡墙厚，先用拓扑图确认每个电池设备都挂在路由器下，别直连协调器。

zwave-js/zwave-js-ui ★ 1.2k 无中文 延伸

Z-Wave JS 的完整控制面板与 MQTT 网关：设备配对、参数配置、网络健康图、OTA，Vue 前端，Docker 部署

→ Zigbee 之外的另一大无线协议，工作在 900MHz 附近，穿混凝土墙比 2.4GHz 强得多，正好对付地堡的厚墙

Z-Wave JS UI 前身叫 zwavejs2mqtt，由 Daniel Lando 主导开发，1.2k 星，是 zwave-js 这个 JavaScript Z-Wave 协议栈的官方控制面板。它要解决的问题是：Z-Wave 设备的配对和配置一直要靠厂商软件，它把这一切放进一个网页，并能把设备桥接成 MQTT。

它的架构是三层：底层 zwave-js 驱动通过串口和 Z-Wave USB 棒通信；中间层提供网页，做设备加入与移除、几百个配置参数的可视化编辑、网络健康图和固件 OTA；上层两条出口，一是 WebSocket 给 HomeAssistant 的 Z-Wave 集成直接用，二是 MQTT 网关给其他系统。Docker 一行部署，也有 HA 加载项。

Z-Wave 工作在 868/908MHz 频段，抗 Wi-Fi 干扰，穿墙比 Zigbee 好，设备都经过认证互操作性强，但贵且国内货少。社区中等规模，2025 年后仍月度更新，界面无中文，中文资料很少。

对 0203 它是延伸里对付厚墙的备选：如果 Zigbee 信号在储藏室和卫生间那几堵混凝土墙后面不稳定，就换一根 Z-Wave 800 棒，用 Z-Wave 温湿度探头和水浸传感器，Long Range 模式一跳就能到。它和 zigbee2mqtt 可以并存，两根棒插同一台服务器，HA 里两个集成互不干扰。注意国内买 Z-Wave 设备要认准 CN 频段的版本，美版 908MHz 在这里不合法也配不上对。
