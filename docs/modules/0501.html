庭院 · 模块 0501 · 柴火堆墙

谁懂啊！一面 3 米半长的柴火墙，比任何背景墙都高级

把过冬的柴火码成一面会呼吸的墙，晒着太阳慢慢变成木屋的燃料。

⬜ 真实项目待设计 #动手主义#自然生活#柴火墙#原木风#DIY

📐 它在哪、有多大

在庭院西边界前，从木屋南墙往南留 30cm 起，沿边界立一排 ≈3.5m 长、0.4m 深、1.6m 高的柴架，切面朝东对着院子；北头挨木屋南门，南头离石墩 ≈0.5m 留出走道；东侧是院子中央的青砖地。（0008 未定位，设想落位）

🎬 沉浸式想象

十一月的下午四点，太阳斜斜地打在庭院西侧那面柴火墙上。你戴着帆布手套，把新劈的香樟段一根根塞进最上层的空格，切面还带着一股樟脑味。墙是用四根杉木立柱撑起来的，中间隔成四个格子，每格 80 厘米宽，码得像一排排书脊。最右边那格留给引火的松枝和竹片，用旧渔网兜着。墙顶一块波浪瓦挡雨，雨水顺着瓦沟滴到下面的碎石带里，滴答滴答。抬头看，柴火之间的缝隙漏出光斑，落在你脚边的青砖上。冬天木屋里那台柴火炉烧的，全是这面墙上今年秋天晒干的木头。

✅ 设想方案清单

  1. 沿庭院西边界立 4 根 10cm 方杉木柱，做成 4 格×0.8m 的柴架，总长约 3.5m，高 1.6m
  2. 底部先铺 15cm 碎石带再架两根横木，柴火离地防潮防白蚁，杭州梅雨天必须
  3. 顶部盖一排旧波浪瓦或镀锌板，前后各出檐 20cm，只挡雨不挡风让柴自然风干
  4. 按树种分格：香樟、栎木、竹子、引火松枝，每格挂一块烙字的小木牌
  5. 靠木屋那头的一格做成柴火炉的『待烧区』，出木屋南门左手就是，动线不超过 8 步
  6. 在柴架侧面钉一块小黑板，用粉笔记每批柴的入库月份，晒满 8 个月再烧
  7. 架顶埋一颗 ESPHome 温湿度小探头，HomeAssistant 看柴火有没有回潮

⚠️ 避坑提醒

  • 别贴着木屋外墙堆，虫子和潮气会顺着爬进屋，至少离墙 30cm
  • 杭州夏天湿热，柴堆底部不架空，三个月就长蘑菇给你看
  • 新柴别急着烧，湿柴烟大还结焦油，炉子烟囱两年就得通

pvvx/ATC_MiThermometer ★ 4.1k 无中文

小米、青萍等 Telink 芯片蓝牙温湿度计的开源替换固件，省电、纯本地广播、直连 HomeAssistant

→ 十几块钱的小米温湿度计刷这个固件塞进柴堆缝里，就是最省事、最便宜的柴火回潮探头

ATC_MiThermometer 是俄罗斯开发者 pvvx 维护的开源替换固件，专门刷进小米、青萍、MHO 等使用 Telink 芯片的蓝牙温湿度计里。原厂固件要绑米家 App、走云端、广播又稀又慢，刷了它以后设备变成一颗纯本地的蓝牙广播探头，一颗纽扣电池能撑一年以上，还多了历史记录和屏幕自定义。pvvx 这个分支功能最全、更新最勤，GitHub 上 4.1k 星。

工作原理很简单：固件通过浏览器网页就能 OTA 刷入，不用拆机也不用烧录器；刷好后设备每隔设定的秒数广播一条 BTHome 或 ATC 格式的数据包，带温度、湿度、电量；HomeAssistant 的蓝牙适配器、ESPHome 蓝牙代理、手机都能收到并解析，无需配对。

它支持 LYWSD03MMC 的六种硬件版本、青萍 CGG1、CGDK2 等十几款设备。README 只有英文，但设备是国产的，B 站和小红书上刷机教程非常多，五分钟搞定。

放进 0501 里，它就是塞在柴堆缝里的回潮探头：买两只十几块的 LYWSD03MMC，刷好固件装进打了透气孔的小塑料盒，一只塞进中层柴缝，一只放架顶对照外界空气；广播间隔调到一分钟，HomeAssistant 做七日均值和 85% 回潮告警。要注意蓝牙可能穿不透木屋砖墙，最好在南窗放一个 ESP32 蓝牙代理接力。

grocy/grocy ★ 9.5k 界面有中文

自托管的家庭物资与库存管理系统，自称冰箱之外的 ERP，支持库存、到期日、家务任务和条码

→ 把四格柴火当四种库存，入库时记日期、到期日设成 8 个月后，晒够了它自动提醒可以烧，家务功能还能排翻晒

grocy 是德国开发者 Bernd Bestel 做的自托管家庭物资管理系统，自称冰箱之外的 ERP，GitHub 上 9.5k 星，是家庭库存这个品类里最出名的开源项目。它最初解决厨房问题：家里有什么、快过期了没有、该买什么；后来长出了家务排班、电池、设备维护等模块，本质是一个带到期日概念的通用库存账本。

它的核心模型是产品、库位和库存条目：每次入库记数量、入库日期和到期日，消耗时扣减，界面按到期时间排序，快到期变黄、过期变红，还能设最低库存触发采购清单。家务模块按固定周期或上次完成时间排期，到点在首页提醒。整个系统是 PHP 加 SQLite，一个 Docker 容器就跑起来，有 REST API 和条码扫描，手机浏览器当 PWA 用。

它通过 Transifex 做多语言，界面有简体中文翻译；HomeAssistant 有社区集成能把库存和家务读成实体；NAS 圈子的中文安装教程很多，2025 年后仍在发版。

在 0501 里，它就是柴架侧面那块小黑板的数字版：建四个产品，香樟、栎木、竹子、松枝，库位就是四个格子；每劈一批柴入库时记日期，到期日填入库后八个月，到期意味着可以烧而不是坏了，语义反过来用；家务模块建一条每月翻晒检查。再让 HomeAssistant 读它的库存实体，和柴缝探头的湿度做双条件判断。要注意 grocy 的单位是数量，柴火按捆或格计最省事，不要去称重。

custom-components/ble_monitor ★ 2.2k 无中文

HomeAssistant 的被动蓝牙传感器集成，不配对只听广播，支持小米、青萍、ATC 固件等上百种设备

→ 柴堆里的 ATC 探头广播出来的数据由它接进 HomeAssistant，顺便把电量、信号强度也变成实体，离线一眼看出

ble_monitor 是 HomeAssistant 社区最早也最完整的被动蓝牙传感器集成，由 custom-components 组织维护，GitHub 上 2.2k 星，2026 年 6 月还在发新版。它解决的问题是：小米、青萍、Govee 这些便宜的蓝牙温湿度计、门磁、体重秤，原本各要各的 App，而它们其实都在不停往空气里广播数据，只要听得懂格式就能直接用。

它的工作方式是被动监听：不配对、不连接，HomeAssistant 主机的蓝牙适配器或 ESPHome 蓝牙代理把收到的广播包转给它，它按厂商格式解析出温度、湿度、电量、信号强度，生成实体，还会做平均和滤波。因为不连接，一个适配器能同时听几十个设备。ATC 和 pvvx 固件的自定义广播格式它原生支持，包括加密广播。

它支持一百多种设备，文档有每种设备的配置示例。没有中文文档，小米设备的中文教程基本都会提到它。

在 0501 里它是探头和中枢之间那一层：柴缝里的 ATC 探头广播，南窗的 ESP32 代理转发，ble_monitor 解析成柴缝湿度、温度、探头电量三个实体，再喂给自动化做七日均值。建议把 period 设成 60 秒和探头广播周期一致，信号强度实体也留着，探头被柴压偏了、信号掉了能第一时间发现。

1technophile/OpenMQTTGateway ★ 4k 无中文 延伸

跑在 ESP32/ESP8266 上的万能网关固件：把 BLE、433MHz、红外、LoRa 收到的东西统统翻译成 MQTT 消息

→ 柴火墙离木屋有一段距离，几颗小米蓝牙温湿度计塞进柴堆比拉线方便，OMG 一块 ESP32 就能把它们全收进 HomeAssistant

OpenMQTTGateway 是法国开发者 Florian Robert 发起的开源网关固件，4k 星，专门解决一件事：家里那些说各种方言的无线小设备（BLE 温湿度计、433MHz 门磁和气象传感器、红外遥控、LoRa 节点）怎么统一接进一个 MQTT 总线。它把一块几十块钱的 ESP32 变成翻译官，收到什么就转成 JSON 发到 MQTT，不用自己写解码。

它的架构是模块化的：每种无线介质是一个 gateway 模块，编译时勾选需要的组合。BLE 模块内置上百种设备的解码器，包括小米 LYWSD03MMC、米家花草监测仪和体重秤，扫到广播包就解出温度、湿度、电量；433MHz 模块解码遥控和无线传感器。输出侧是 MQTT，原生支持 HomeAssistant 自动发现，设备一上线 HA 里就冒出实体。

生态上它有网页版刷机工具，浏览器插上板子点一下就能刷，官方支持十几种现成开发板。社区在 Discord 和 Discussions 上活跃，2025 年 1 月发布了 1.8.1 版。文档全英文，中文只有零散博客。

在 0501 里它是延伸玩法：方案里柴架顶只埋一颗 ESPHome 探头，但四个格子的柴干湿并不一样。买四颗二十块的小米温湿度计塞进每格柴堆深处，木屋南墙下放一块跑 OMG 的 ESP32 做 BLE 网关，四格温湿度就全进了 HA，配合前面 ATC_MiThermometer 的固件广播里还带电量。注意柴堆会吸收蓝牙信号，网关别离柴架超过 5 米。

espressif/esp32-camera ★ 2.8k 无中文 延伸

乐鑫官方的 ESP32 摄像头驱动库，支持 OV2640/OV5640 等常见传感器，输出 JPEG 或 RGB 帧，是所有 ESP32-CAM 项目的底层

→ 十几块钱的 ESP32-CAM 装在院子对面，每天定点拍一张柴火墙，一年拼成延时看柴怎么被烧空又码满

esp32-camera 是乐鑫官方维护的摄像头驱动库，2.8k 星，几乎所有 ESP32-CAM 板子、ESPHome 的 esp32_camera 组件、Arduino 的 CameraWebServer 示例，底层用的都是它。它解决的是最基础的问题：ESP32 没有专门的相机接口，要靠 I2S 并口把 OV2640、OV5640 这些图像传感器的数据搬进内存，再压成 JPEG。

它的工作流程是：初始化时按板子引脚配置传感器，选分辨率、像素格式和帧缓冲数量；调用一次 fb_get 就拿到一帧，用完 fb_return 还回去。库里附带 BMP 和 JPEG 转换工具，还能调亮度和白平衡。ESP32 内存有限，高分辨率必须靠 PSRAM。

生态非常庞大：ESPHome 直接把它包成了组件，HomeAssistant 里就能看画面和抓图；Arduino、ESP-IDF 都有绑定。中文资料极多，淘宝的 ESP32-CAM 教程基本都围绕它。

在 0501 里它是延伸：柴火墙本身不需要摄像头，但那面墙一年的变化本身就是个故事。在院子东侧对着柴架装一块 ESP32-CAM，用 ESPHome 每天中午拍一张存到 0802 家庭服务器；十一月码满、二月烧空、香樟切面从黄变灰，365 张拼成延时。顺手做个小自动化：HA 比较最新一张和上周的亮度差，某格突然变亮就是快空了，提醒该劈柴。注意镜头朝西拍柴墙，下午会逆光，中午拍最稳。
