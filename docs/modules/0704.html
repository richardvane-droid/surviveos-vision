钓台 · 模块 0704 · 水边茶席·小火塘

松弛感天花板：钓台上挖了个小火塘，煮茶烤鱼看月亮

一方矮桌一壶茶，一个铁盆小火塘，钓上来的鱼当场烤，一个人也能坐到月亮出来。

设想 真实项目尚未拆解此区域 #围炉煮茶#松弛感#人类丰容#烤鱼#观鸟

📐 它在哪、有多大

小火塘嵌在钓台靠坡一侧的角上，40cm 见方；矮桌 60×40cm 贴火塘南边，一个蒲团面朝河；整个茶席占台面 ≈1.5㎡，剩下的留给椅子和鱼竿。（0008 未定位，设想落位）

🎬 沉浸式想象

傍晚六点半，你把今天的鲫鱼刮好鳞，抹上盐插在竹签上。钓台角上那个小铁盆火塘里，柴火炉那边搬来的几根松木劈柴已经烧成红炭，鱼架在炭上滋滋响。矮木桌上一把粗陶茶壶坐在小炭炉上，水开了咕嘟咕嘟。你盘腿坐在蒲团上，手里一杯龙井，脚边水面把火光晃成一片碎金。风从河对岸吹过来，带着一点烤鱼的焦香和芦苇的味道。你抬头，月亮从竹林上面爬出来，没人说话，只有炭响，鱼快熟了。

✅ 设想方案清单

  1. 钓台靠坡一侧的角上开一个 40cm 见方的口，嵌一只铸铁小火盆，底下垫一块 5cm 厚的火山岩板隔热
  2. 火盆上架一个可旋转的三脚吊架，能挂水壶也能架烤网，高度用链条调
  3. 一张 60×40cm 的老榆木矮桌，桌腿锯短到 30cm，火塘边只放一个蒲团，面朝河
  4. 顶棚正上方留一个 40cm 的透气口，加一个竹编罩子，烟往上走不熏人
  5. 茶具用一套粗陶：一壶一杯一个小茶盘，收在矮桌下面的木抽屉里，防潮
  6. 火塘旁边固定一个小竹筒当柴桶，装从柴火堆墙拿来的劈柴，够烧一个人的一晚
  7. 台边装一只铁皮水桶，专门存水灭火，规矩是走之前必须浇一遍

esphome/esphome ★ 11.7k 无中文（社区教程多）

用 YAML 配置 ESP32 固件的系统，一氧化碳、温度探针、脉冲风速、本地定时器都是现成组件，本地跑不上云，原生接 HomeAssistant

→ 火塘空气看护和煮茶烤鱼计时器合成一块 ESP32：读 CO 传感器和热电偶，本地阈值报警和倒计时，不靠 Wi-Fi 也能响蜂鸣器

ESPHome 是 Nabu Casa 维护的 ESP32 固件生成系统，和 HomeAssistant 同一个团队，GitHub 上 11.7k 星。想让 ESP32 读传感器、控蜂鸣器、跑一点判断逻辑，以前得写 Arduino 代码，而它只要一份 YAML 写清接了什么、往哪报，编译、烧录、OTA 全自动，HomeAssistant 自动发现。

它的工作方式是 YAML 到 C++ 的编译器：声明传感器型号、引脚、采样周期，它生成固件；固件在设备本地运行，原生 API 推给 HomeAssistant，断网时本地逻辑照常。和火塘相关的组件都有：max31855 读 K 型热电偶，dallas 读防水温度探头，uart 加外部组件读炜盛 ZE07 一氧化碳传感器，script 做本地倒计时，rtttl 让无源蜂鸣器唱几个音。没有官方中文，但中文社区极大，B 站教程数不清。

在 0704 里它做一块塞在矮桌抽屉后面的火塘小板：一颗 ZE07 一氧化碳传感器装在顶棚透气口下方，读数超过 50ppm 持续五分钟蜂鸣器响并推手机，超过 100ppm 立刻响，逻辑全在本地不看 Wi-Fi；一根 K 型热电偶插进烤鱼的炭层、一根 DS18B20 贴茶壶，温度到了各响一声不同的调；再加一个按钮启动三分钟泡茶倒计时。所有实体进 HomeAssistant，矮桌下的墨水屏顺手显示炭温和茶温。CO 传感器要预热且怕烟熏，装在烟不直冲的位置；热电偶线加陶瓷套管。

CapnBry/HeaterMeter ★ 556 无中文

开源烧烤温控器，Arduino 板加树莓派跑 LinkMeter，四路探针，PID 控鼓风机和风门保持炭火温度，网页看曲线和报警

→ 火塘要烤鱼又要煮茶，靠它的 PID 鼓风把炭温稳在 200 度左右，四路探针一根测炭一根插鱼，网页曲线比盯着火看准

HeaterMeter 是美国开发者 Bryan Mayland 从 2010 年起做的开源烧烤温控器，GitHub 上 556 星，硬件电路、Arduino 固件和树莓派端软件全部开源，是 DIY 烧烤圈子里最经典的项目。它解决的问题是：用炭火烧烤最难的是把温度稳住，人要不停调风门，而它用一个小鼓风机和 PID 算法自动补氧减氧，让炭火像烤箱一样恒温。

它的结构是两块板：一块 Arduino 兼容的主板插四路热敏探针，跑 PID 算法，按目标温度和实测温度输出 PWM 给鼓风机和舵机风门，脱机也能独立工作，板上有小屏和旋钮；主板插在一块树莓派上，树莓派跑名为 LinkMeter 的 OpenWrt 固件，提供网页界面，实时画四路温度曲线、设目标温度、设报警，报警通过邮件、推送和脚本发出，也有 MQTT 转发的社区方案。硬件可以按仓库的 Gerber 自己打板，也能买套件。没有中文资料，但烧烤论坛上讨论极多。

在 0704 里它管火塘的炭温：铸铁火盆侧面开一个小口接鼓风机的软管，主板和树莓派装在矮桌下的抽屉隔间里，四路探针一根插在炭层测火塘温度，一根插进烤鱼最厚处，另外两根留给煮茶壶和第二条鱼；网页上设炭温目标 200 度，它自动鼓风，鱼内部到 65 度手机响。烤完关鼓风机让炭自然熄，走之前照规矩浇水。要注意开放火塘不像封闭烤炉那样好控，鼓风只能提温不能降温，风大的晚上把目标设低一点；探针线耐温有限，别直接搭在炭上。

WLANThermo-nano/WLANThermo_ESP32_Software ★ 40 无中文

德国开源 ESP32 烧烤温度计固件，最多八路探针、网页和手机 App、推送通知、Pitmaster 功能控风扇或舵机、MQTT

→ 比 HeaterMeter 轻：一块 ESP32 就够，烤鱼和茶壶各插一根探针，温度到了手机提醒，MQTT 进 HomeAssistant，德国社区维护十年

WLANThermo 是德国一个开源社区从 2014 年起做的烧烤温度计项目，这个仓库是它 ESP32 一代的固件，GitHub 上 40 星，README 是德文。它解决的问题和 HeaterMeter 一样，把烤肉时的温度监控和炭火控制交给机器，但路线更轻：不用树莓派，一块 ESP32 加一块探针板就是完整设备，网页、App、通知都在这颗芯片上。

它的结构是 ESP32 固件加两代硬件，Nano V3 有八路探针口，Mini V3 有四路，探针是标准的 NTC 热敏电阻，支持多种品牌的探针型号，也能接蓝牙探针。固件提供本地网页界面和手机 App，每路设上下限，越界通过 Telegram 等推送；Pitmaster 功能是它的温控部分，一路探针做反馈，用 PID 输出给风扇或舵机风门；数据可以走 MQTT 发出去。硬件设计和外壳文件在同一组织的其他仓库里，可以自己打板或买套件。没有中文资料，德文文档靠翻译软件能看懂。

在 0704 里它是比 HeaterMeter 更省事的选择：一块 Nano V3 装在矮桌抽屉里，两根探针分别插进烤鱼和贴在茶壶上，各设一个上限，鱼 65 度、茶壶 95 度，到了 App 推一条；MQTT 接进 HomeAssistant 后，温度显示在 0703 那块能源卡片旁边。想控火再接一个小风扇到火盆进风口，用 Pitmaster 稳炭温，不行就当纯温度计用。NTC 探针型号要在设置里选对，否则读数偏几十度；进炭层的那根探针要用耐高温款。

fishaudio/fish-speech ★ 31.8k 官方中文 README 延伸

开源的顶级文本转语音模型：中英日等多语言，几秒参考音频即可克隆音色，自然语言标签控制情绪，本地 GPU 或 CPU 推理

→ 火塘边不想看屏幕，想让一个熟悉的声音念一首诗、报一句火候，本地跑、中文自然、音色可以是自己人

Fish Speech 是国内团队 Fish Audio 2024 年开源的文本转语音模型，31.8k 星，2025 年推出 S2 Pro 版本，仓库自带中文 README，是中文开源 TTS 里最接近商业水准的一个。它解决的问题是：以前的开源 TTS 要么机械要么只有英文，中文语音想自然、想用自己的音色，得靠云服务。

它的工作方式是两段式：先把文本用大语言模型架构转成语义音频 token，再由声码器把 token 还原成波形。给它几秒钟的参考音频就能零样本克隆音色，不用训练；文本里可以写情绪和语气的自然语言标签，比如慢一点、带笑意。推理支持 NVIDIA 显卡、AMD 显卡和纯 CPU，带命令行、WebUI 和 HTTP API，Docker 一键起。

生态上它的社区在国内很活跃，B 站教程多，Discord 和 QQ 群都有人答疑。要注意模型采用 Fish Audio 研究许可证，个人和研究用途没问题，商用要另谈。

在 0704 里它是延伸：火塘边的规矩是不看手机，那就让声音来。在 0802 服务器上跑 Fish Speech 的 HTTP 服务，HomeAssistant 通过一个自定义 TTS 集成调用它，参考音频用家里人念的十秒话。傍晚开火时，0208 的 Snapcast 分一路到钓台顶棚下的小音箱，念一首和季节对上的诗；水壶温度探头到 90 度报一句水快开了；走的时候报一句别忘了浇火。文本从 0209 的名言库里按日期挑，声音是自己人的，比任何音箱助手都合适。

openai/whisper ★ 107.3k 无中文 延伸

OpenAI 开源的语音识别模型：68 万小时数据训练，99 种语言含中文，本地推理，自动断句加标点，可翻译成英文

→ 火塘边说的话比写的多，鱼获、火候、今天想到的事，对着手机说一段，转成文字才能进 0702 的钓鱼笔记

Whisper 是 OpenAI 2022 年 9 月开源的语音识别模型，107.3k 星，是 GitHub 上星数最高的语音项目，MIT 许可证，2024 年又加了更快的 turbo 版。它解决的问题是：以前离线语音识别对口音、噪音和中文都很差，Whisper 用 68 万小时网络音频弱监督训练，做到接近商业水平。

它的工作方式是把音频切成 30 秒的窗口，转成梅尔频谱输入一个编码器解码器 Transformer，解码器一边识别语种一边输出带标点的文本。模型从 tiny 到 large 有六档，tiny 在树莓派上也能跑，large 要显卡。周边最重要的两个衍生项目是 C++ 重写的 whisper.cpp 和更快的 faster-whisper，HomeAssistant 的语音助手管线就是靠 Wyoming 协议接 faster-whisper 做听写。

生态上中文资料非常多，B 站和知乎教程从装包到微调都有，中文识别效果在 medium 以上模型很稳。

在 0704 里它是延伸：火塘边坐着的时候，想记的东西很多但不想掏笔。手机上用 HA 伴侣应用按住说一段，比如今天两条鲫鱼一条昂刺、松木炭烤鱼十分钟正好，音频传到 0802 服务器的 faster-whisper 转成文字，自动化按关键词分流：有鱼名的进 0702 的钓鱼笔记，其他的进 0209 的 memos。想更省事就在钓台柱子上装一只 ESP32-S3 语音盒子，唤醒词一喊，灯、音乐和记笔记都能用嘴说。

OHF-Voice/piper1-gpl ★ 5.1k 无中文 延伸

Piper 的官方续作：Open Home Foundation 维护的轻量本地 TTS，ONNX 模型在树莓派上实时出声，几十种语言含中文普通话

→ 念诗交给 Fish Speech，但火快灭了、水开了这种一句话提示不值得开显卡，需要一个几十毫秒就出声的小引擎

Piper 是 Rhasspy 作者 Michael Hansen 2022 年做的轻量神经 TTS，11k 星的老仓库 2025 年 10 月归档，开发转到 Open Home Foundation 名下的 piper1-gpl，5.1k 星，GPL 许可证，是 HomeAssistant 官方语音助手默认的说话引擎。它解决的问题是：大模型 TTS 好听但要显卡、要等几秒，家里的提示音需要在树莓派上几十毫秒出声。

它的工作方式是把文本先经 espeak-ng 转成音素序列，再送进 VITS 架构的模型，用 ONNX Runtime 一次性生成波形，不需要 GPU。每个语音是一个几十兆的 .onnx 文件加配置，官方提供几十种语言上百个音色，中文有普通话女声 huayan，也能用自己的录音训练。Python 包、命令行和 HTTP 服务都有，HA 通过 Wyoming 协议直接接。

生态上它在 HA 语音社区里是默认选项，文档英文，中文教程集中在 HA 中文论坛和 B 站，注意中文音色的自然度不如 Fish Speech，但胜在秒出声。

在 0704 里它是延伸，和 Fish Speech 分工：念诗这种长段落走 Fish Speech，慢一点没关系；水壶探头到温度、柴桶重量传感器提示柴快烧完、离开钓台前提醒浇水灭火，这种一句话的提示走 Piper，HA 语音管线里把它设为默认 TTS，响应快，服务器不用喂显卡。以后装了 ESP32 语音盒，问一句电池还有多少，回答也是它。
