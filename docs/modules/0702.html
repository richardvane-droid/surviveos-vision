码住！钓台边一面洞洞板，把鱼竿、假饵、抄网全挂成了一幅画

一面防水洞洞板 + 一个老木箱，钓具不再乱塞，每一件都像展品。

设想 真实项目尚未拆解此区域 #痛屋#收纳#工业风#钓鱼#数字孪生

📐 它在哪、有多大

洞洞板挂在钓台靠坡一侧（北侧）的两根杉木柱之间，≈0.9×1.5m，背对缓坡、面朝河；老木箱垫砖放在板下台面上，≈60×40cm；整个储物角占台面不到 0.5㎡，留出中间一人一椅的位置。（0008 未定位，设想落位）

位置与尺寸依据 0008 户型图与空间标注 v1；≈ 为按图面比例预估、未实测。看户型图 →

🎬 沉浸式想象

太阳落到竹林后面，你收竿上岸，走到钓台靠坡那头的储物墙。洞洞板上三根鱼竿按长度斜着排开，最上面那根是爷爷留下的老竹竿。你把今天用的路亚假饵一个个挂回小钩子上，铁片饵在余光里闪了一下。脚边的老樟木箱盖子一掀，一股樟木味混着鱼腥味涌出来，里面分格放着线轮、铅坠和一本翻烂的《钓鱼笔记》。你在笔记上写下：9 月 3 日，晴，两条鲫鱼一条昂刺，用的黄色软虫。合上箱子，拍拍手，明天再来。

✅ 设想方案清单

  1. 钓台靠坡一侧两根杉木柱之间挂一面 0.9×1.5 米的洞洞板，用防腐胶合板 + 三遍船用清漆，孔距 25mm 通用挂钩
  2. 三根鱼竿用一组斜向竿托挂成扇形，短竿在下长竿在上，一眼看出长度
  3. 假饵和小配件用透明亚克力小盒分类，盒子背后贴磁铁吸在一块铁板上，随手取放
  4. 板下放一只 60×40cm 的老樟木小箱当主储物，内部用薄木板分成六格：线轮、铅坠、钩、浮漂、工具、杂物
  5. 洞洞板顶部装一块小木檐板挡雨，下雨天板面基本淋不到
  6. 一个角落钉一块小黑板，用粉笔记录每次的鱼获和天气，写满了拍照存档再擦
  7. 挂一个铁皮小盒专门放 PSK 生存盒里的钓鱼组件，顺便做产品展示

🔥 小红书灵感点

  • 「痛屋」思路：把钓台储物墙当成钓鱼主题的痛墙，假饵按颜色排成渐变，出片率爆表
  • 「物品数字孪生」话题：每根竿贴一个 NFC 标签，手机一碰就知道上次用它钓了什么
  • 「废墟风」老木箱：闲鱼淘一只带包浆的樟木箱，不打磨不上漆，越旧越对味

⚠️ 避坑提醒

  • 普通洞洞板放水边半年就发胀分层，一定要防腐板 + 船用漆，别省这几十块
  • 鱼竿别横着放太久，竿稍会弯，斜挂或竖挂才对
  • 樟木箱别直接放地板上，垫两块砖，下面通风不然底板先烂

sysadminsmedia/homebox ★ 7.1k 界面有中文

面向家庭的自托管物品库存系统，位置嵌套、标签、照片、自定义字段、可打印的二维码标签和维护记录，Go 写的单容器，界面有简体中文

→ 洞洞板、樟木箱六格、亚克力饵盒各建成位置，每根竿每盒饵一条记录贴二维码，扫一下知道在哪、上次换线是什么时候，PSK 组件也在里面

HomeBox 最早由开发者 hay-kot 做，2024 年后由 sysadminsmedia 团队接手继续维护，GitHub 上 7.1k 星，是自托管圈子里最流行的家庭物品库存系统。它解决的问题是：家里的东西越来越多，放在哪、什么时候买的、保修到几时、多久没维护，靠记忆管不住，而企业级资产管理软件又太重。

它是 Go 后端加 Vue 前端的单容器应用，默认 SQLite，一条 Docker 命令起来。核心结构是位置、标签、物品三层：位置可以无限嵌套，比如钓台、洞洞板、樟木箱第三格；物品有名字、数量、照片、购买信息、序列号、自定义字段和附件，还有维护日志记录每次保养；标签横向分类。最实用的是二维码标签生成器，按物品或位置批量出可打印的标签纸，手机扫码直接打开那件东西的页面；还有 CSV 导入导出、多用户和通知。界面通过 Weblate 翻译，有简体中文。

在 0702 里它是钓具的电子账本：位置树建成钓台、洞洞板、樟木箱六格和磁吸饵盒，三根鱼竿、每个线轮、每盒假饵各建一条，照片就用手机拍，自定义字段记线号和上次换线日期；打印二维码贴在竿托、饵盒背面和樟木箱格子里，取用时一扫就知道这盒饵上次用在哪天。PSK 生存盒的钓鱼组件也建成一个位置，兼做产品清单。要注意它是库存不是渔获日志，鱼获和天气交给专门的钓鱼 App；二维码标签要用防水的合成纸贴纸，普通纸在河边一个夏天就糊了。

kennetek/gridfinity-rebuilt-openscad ★ 2.2k 无中文

Gridfinity 模块化收纳系统的 OpenSCAD 重写版，参数化生成 42mm 网格的分格盒和底板，底部自带磁铁孔，改几个数字就出 STL

→ 樟木箱六格和磁吸饵盒不用手工分板：按格子内尺寸生成 Gridfinity 分格盒打印出来，底部磁铁孔正好吸在洞洞板下的铁板上

gridfinity-rebuilt-openscad 是开发者 kennetek 用 OpenSCAD 重写的 Gridfinity 生成库，GitHub 上 2.2k 星。Gridfinity 是 Zack Freedman 在 2022 年提出的开源模块化收纳标准：所有盒子都按 42 毫米网格和 7 毫米高度单位来做，放在同样网格的底板上就自动对齐。原始设计是 Fusion 文件，这个仓库把它变成纯代码，改几个参数就能生成自己的盒子。

用法是在 OpenSCAD 里打开 bins 文件，用定制面板填长几格、宽几格、高几单位、内部分几格、要不要取物斜面和标签槽、底部要不要磁铁孔，点一下就出模型，导出 STL 去打印；另一个文件生成底板。底部磁铁孔按 6×2 毫米磁铁设计，压进去就是磁吸底。仓库有详细参数文档，社区围绕 Gridfinity 有上万个衍生模型。没有中文资料，但参数名直白。

在 0702 里它做两件事：樟木箱内部不用薄木板分格，而是量出箱内尺寸，生成一块底板和六个不同分格的盒子，线轮盒深一点、钩和铅坠盒分小格带斜面方便手指挑；磁吸饵盒就是带磁铁孔的浅盒加透明盖，吸在洞洞板下方那块铁板上随手取放。打印用 PETG 而不是 PLA，晒过的钓台温度能让 PLA 变形。箱内尺寸未必是 42 的整数倍，空隙用半格模块或垫条补；磁铁选镀镍防锈。

cohenadair/anglers-log ★ 34 无中文

Flutter 写的开源钓鱼日志 App，iOS 和安卓都有，记渔获照片、鱼种、饵、钓点、天气潮汐，出统计报表，两千多次提交长期维护

→ 小黑板写满拍照后的数字版：每条鱼记鱼种、饵、天气，一查就知道哪种饵在哪个月最好用，代码开源但成品 App 直接装最省事

Anglers Log 是加拿大开发者 Cohen Adair 从 2014 年起维护的钓鱼日志 App，最初是 iOS 和安卓两套代码，2020 年后用 Flutter 重写成一套，GitHub 上 34 星，两千多次提交，应用商店里有成品。它解决的问题是：钓鱼的人都想知道自己在什么天气、什么饵、什么时段最容易上鱼，这需要长期、结构化的记录，本子上记的东西没法统计。

它的结构是本地数据库加可选云备份：核心对象是渔获，每条记录鱼种、长度重量、照片、用的饵和钓法、钓点坐标、时间，以及自动抓取的天气、气压、潮汐和月相；渔获归到一次出钓里，出钓再记同行的人。报表按鱼种、饵、钓点、月份交叉统计，画出上鱼最多的组合；鱼种、饵、钓点都是可自定义的字典。没有中文界面，但字段少，用起来不需要看字。

在 0702 里它是小黑板的数字版：黑板上用粉笔写今天几条鲫鱼、什么饵、什么天气，拍照存档后再把每条录进它，鱼种字典预先建好鲫鱼、昂刺、鲤鱼、翘嘴，饵字典建好洞洞板上那几盒假饵和常用的蚯蚓玉米；钓点就一个，河边钓台。半年后看报表，黄色软虫在九月傍晚上鱼最多这种结论就出来了，反过来决定哪盒饵挂在最顺手的位置。它的天气数据来自国外气象服务，乡下精度一般，气压和月相更可信；备份定期导出，别只存手机。

manyfold3d/manyfold ★ 2.1k 无中文 延伸

自托管的 3D 打印文件管理器：扫描硬盘上的 STL/3MF，网页里预览、打标签、记来源和授权，支持联邦分享

→ 洞洞板挂钩、竿托、亚克力盒卡座、樟木箱分格件都是打印的，模型文件散在硬盘里，得有一个库让坏了能立刻找到再打一件

Manyfold 是英国开发者 James Smith 2022 年开始做的自托管 3D 模型库，2.1k 星，Ruby on Rails 编写，Docker 一条命令部署，2025 年仍在密集更新。它解决的问题是：从各个网站下载的 STL 越攒越多，文件夹里全是 model_final_v3，想再打一件洞洞板挂钩时根本记不起是哪个。

它的工作方式是扫描你指定的文件夹，把每个子目录识别成一个模型，网页里用 three.js 渲染三维预览，可以加标签、写说明、记录原始来源链接和授权协议；文件重命名和整理可以按模板自动做。它支持 STL、OBJ、3MF 等主流格式，能从 Thingiverse 等网站导入元数据，还实现了 ActivityPub 联邦协议，两台 Manyfold 之间可以互相关注和分享模型，把打印圈的分享做成了去中心化的样子。

生态上它有活跃的 Discord 和 Mastodon 社区，界面有多语言翻译，简体中文翻译不完整，文档全英文。

在 0702 里它是延伸：钓具储物角有一堆打印件，通用挂钩、扇形竿托的斜托座、亚克力盒背后的磁铁座、樟木箱的六格分隔条，还有 Gridfinity 小格子。在 0802 服务器上跑一个 Manyfold，把这些模型集中进来，打上 0702 钓具 和 0701 钓台 标签，说明里写清楚用了什么耗材和打印参数。哪天竿托被大鱼拽断了，手机打开 Manyfold 找到文件，扔给 0305 的打印机就行，不用重新翻硬盘。

tesseract-ocr/tesseract ★ 75.9k 无中文 延伸

最著名的开源 OCR 引擎：谷歌维护多年，LSTM 神经网络识别一百多种文字，命令行和 C++/Python 接口，输出文本或可搜索 PDF

→ 小黑板上的鱼获记录写满就拍照擦掉，照片里的字要能变成可搜索的文本，才能真的攒成一本钓鱼笔记

Tesseract 是惠普 1985 年开始研发、2005 年开源、后来由谷歌维护多年的 OCR 引擎，75.9k 星，现在由社区在 GitHub 上继续更新，5.x 版基于 LSTM 神经网络。它解决的问题是把图片里的文字变成可以搜索、复制、统计的文本，是几乎所有开源文档工具背后的那个引擎。

它的工作方式是先用 Leptonica 库做图像预处理，二值化、去斜、切分行和字，再把每行送进 LSTM 网络识别成字符序列，最后按版面输出纯文本、hOCR、TSV 或带文字层的 PDF。语言包按需下载，简体中文是 chi_sim，还能用自己的样本微调训练。命令行一句话就能跑，Python 有 pytesseract 封装，几乎所有语言都有绑定。

生态上它是 paperless-ngx、OCRmyPDF 等项目的底层，文档全英文，中文教程极多，装包和调参的坑都被踩遍了。要注意它对印刷体很好，对手写体尤其是粉笔字识别率明显下降，需要靠预处理和事后校对补。

在 0702 里它是延伸：小黑板写满一板鱼获和天气后拍照存档，照片扔进 0802 服务器上的一个监视目录，脚本先用 ImageMagick 把黑底白字反转成白底黑字并加大对比度，再用 Tesseract 的 chi_sim 识别，结果作为草稿推到手机上校对一遍，确认后写进 anglers-log 或 0209 的 memos。粉笔字写得工整一点、日期用阿拉伯数字，识别率会高很多。
