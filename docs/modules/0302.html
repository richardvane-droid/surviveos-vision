阁楼间 · 模块 0302 · 户外装备区

被问爆了！我把阁楼斜顶做成了一面“户外装备展示墙”

登山包、睡袋、炉头全部挂上墙，像户外店一样一眼看全，出发只要 5 分钟。

⬜ 真实项目待设计 #痛屋#户外风#露营风#装备墙#去家务化

📐 它在哪、有多大

放在 03 阁楼间西侧的低矮带：西墙到可站立区之间 ≈2m 宽、5m 长的斜顶下，紧挨 0303 帐篷西侧；格子柜贴檐口最矮处，登山包挂在斜顶龙骨上。（0008 未定位，设想落位）

🎬 沉浸式想象

凌晨五点半，你打着头灯爬上阁楼，准备去临安徒步。帐篷西边那片斜顶上，三只登山包按 20L、38L、65L 从小到大挂着，下面一排挂钩上是登山杖、水袋、雨衣。檐口最矮处的木格子里，睡袋和防潮垫卷成圆筒立着，像一排葡萄酒。你拎下 38L 那只，从格子里抽一个炉头、一罐气、两包速食，背上就走。墙上贴着一张手写的“出发清单”，每样东西对应一个格子，空格子就是你忘带的东西。天窗外天刚蒙蒙亮，阁楼里有一股淡淡的防水喷剂味。

✅ 设想方案清单

  1. 帐篷西侧的斜顶钉整面松木条挂板，用大号 S 钩挂三只登山包，按容量从小到大排
  2. 檐口最矮处做 30×30cm 木格子柜，睡袋、防潮垫卷起立放，每格贴标签
  3. 炉头、气罐、头灯、刀具单独放一个带盖收纳箱，箱盖内侧贴使用说明
  4. 墙上贴一张“出发清单”手写板，按日徒步 / 两日露营 / 钓鱼三条线列
  5. 装一个小除湿盒 + 温湿度传感器接 HomeAssistant，湿度超 70% 推送提醒
  6. 格子柜和帐篷之间留一块 1 米宽的“整备区”地垫，回来先在这里晾装备再上墙
  7. 登山鞋放最下面一排斜格，鞋头朝外，和帐篷区共用一台小烘鞋器

🔥 小红书灵感点

  • “痛屋”概念：把户外装备当收藏品陈列，一面墙就是我的兴趣主题房
  • 户外店陈列法：同类装备成排、由小到大，拍照特别出片
  • “去家务化”动线：装备回来先晾再上墙，每样东西只有一个家

⚠️ 避坑提醒

  • 阁楼夏天很热，气罐别贴着檐口最矮处放，屋面晒透了那里最烫
  • 睡袋长期压缩会失去蓬松度，一定要松放或挂起
  • 别买太多同类装备，格子满了就停，格子就是预算

🔧 GitHub 上的成熟方案

按知名度（星数）优先、有中文版优先挑的开源项目，每个都在 2026-09 打开核实过存在。每个方案配一段科普介绍和一张铅笔风的“它怎么工作 + 怎么接进本模块”示意图。

esphome/esphome ★ 11.7k 无中文（社区教程多）

用 YAML 配置文件给 ESP32 / ESP8266 生成固件的开源系统，传感器、继电器、屏幕原生接入 Home Assistant

→ 装备区那只温湿度传感器加除湿盒插座就是一段二十行的 YAML，湿度超 70% 推送、超 75% 自动开除湿，不用写一行 C

ESPHome 是 Otto Winter 在 2018 年创立、现在由 Home Assistant 背后的 Nabu Casa 维护的开源固件生成系统，11.7k 星，几乎每两周发一版。它解决的问题是：想把几十块钱的 ESP32 变成家庭自动化平台看得见的传感器或开关，以前要写 Arduino、MQTT、OTA，现在只要写一份 YAML。

YAML 里声明用哪块板子、接了哪个传感器、哪个引脚、多久上报，ESPHome 就把它翻译成 C++、编译成固件，通过 USB 或 Wi-Fi 刷进板子。板子跑起来后用原生 API 和 HA 直连，HA 里自动出现实体，也能走 MQTT。它内置三百多种组件：温湿度、气压、颗粒物、CO2、电流互感器、继电器、步进电机、墨水屏、蓝牙代理，还能在 YAML 里写小段 lambda 做本地逻辑，断网照跑。

它和 HA 是一家人，HA 加载项里点一下就装好编辑器和编译环境；官方文档只有英文，但国内教程、B 站视频和现成 YAML 极多。

在 0302 里它承担“装备湿度看护”：一块 ESP32-C3 加 SHT30 挂在格子柜内侧，YAML 里加 sht3xd 组件每 60 秒上报，HA 自动化做两级阈值——湿度过 70% 推送手机提醒，过 75% 打开除湿盒的智能插座，回落到 60% 再关，带迟滞避免反复开关。注意斜顶下夏天闷热，板子别贴着瓦面装。

sysadminsmedia/homebox ★ 7.1k 界面有中文

面向家庭用户的自托管物品库存系统，支持位置树、标签、附件、维护记录和二维码标签打印

→ 每个木格子和收纳箱都是一个位置，贴上它打印的二维码，扫一下就知道气罐还剩几罐、头灯上次换电池是什么时候

HomeBox 最初由 Hayden 在 2022 年用 Go 和 Nuxt 写成，2024 年作者停更后由 sysadminsmedia 社区接手维护，现在 7.1k 星，是自托管家庭物品库存里最轻量、最好上手的一个。它解决的问题很朴素：家里的东西在哪、有几个、什么时候买的、保修到哪天，而不是企业 ERP。

它的结构是三层：位置（Location）可以嵌套，比如阁楼间 → 装备区 → 格子柜第三格；物品（Item）挂在位置下，记数量、购买价、序列号、图片、说明书附件，还能写维护日志；标签（Label）横向分类，比如露营、钓鱼、消耗品。每个位置和物品都有一个二维码，网页里可以按 Avery 标签纸批量生成 PDF 贴纸，手机扫码直接跳到那一页。后端是单个二进制加 SQLite，一条 Docker 命令起服务。

它有官方镜像、HA 社区加载项、Weblate 维护的多语言界面，简体中文翻译完整；文档是英文，但界面全中文，国内 NAS 玩家用得不少。

在 0302 里它是“出发清单核对器”的库存底座：格子柜每一格、带盖收纳箱各建一个位置，气罐、速食按数量记，头灯电池、炉头清洗写进维护记录；标签打出来贴格子口。LighterPack 负责“带什么、多重”，HomeBox 负责“在哪、剩几个”。注意它没有“借出”状态，装备拿走要靠 0401 的去向卡或 HA 的 NFC 事件补。

galenmaly/lighterpack ★ 800 无中文

户外圈最常用的装备清单网站 LighterPack 的源码，可自部署，按分类算总重和背负重量

→ 把墙上那张手写出发清单搬进去，日徒步、两日露营、钓鱼三条线各存一份，背包重量自动算，出门前一格格核对

LighterPack 是美国开发者 Galen Maly 从 2013 年起做的装备清单网站，全世界轻量化徒步玩家都用它晒装备表，源码开源，800 星，Node.js 加 MongoDB，可以自己部署一份不依赖官网。它解决的问题是：一次出行到底带了什么、多重、哪些穿在身上、哪些是消耗品，以及怎么把清单变成一眼看懂的图。

它的数据模型是“清单 → 分类 → 物品”：一份清单叫一个 list，里面按睡眠、炊事、穿着、电子等分类，每件物品记名称、重量、数量、价格，可以标记为穿戴或消耗品。系统实时算出基础重量、穿戴重量、消耗品重量和总重，右侧画一个饼图，导出成分享链接或 CSV。同一件物品可以拖进多份清单，所以“日徒步”“两日露营”“钓鱼”三条线各存一份、共用一个装备库很自然。

它没有中文界面，但物品名随便写中文，国内户外论坛也常见用它晒表；更新不频繁，功能早已够用。

在 0302 里它接管墙上的“出发清单”：三条线各一份 list，出门前打开手机对着格子逐项打钩，空格子就是没带的东西；每次回来称一次实际重量校正数据。它只管“带什么”，库存数量交给 HomeBox；两边都用同一套物品名，扫码能对得上。注意自部署要跑 MongoDB，放在 0801 的小主机上就行。

organicmaps/organicmaps ★ 15.3k 界面有中文 延伸

隐私优先的离线地图与 GPS 导航 App：OSM 数据、等高线、徒步骑行路线规划，全程无网可用、无广告无追踪

→ 装备区的出发清单对应的是山里没信号的路线，Organic Maps 把临安一带的离线地图和轨迹记录装进手机，是背包之外的第一件装备

Organic Maps 是从 MAPS.ME 分叉出来的社区项目，用 C++ 写核心、原生 Android 和 iOS 客户端，15.3k 星，全球用户超过六百万。它要解决的问题是：徒步进山后手机没信号，商业地图 App 要么下不到离线包，要么满屏广告和追踪。Organic Maps 完全离线、不联网、不收集数据。

它的工作方式是把 OpenStreetMap 数据按地区预处理成自家的 mwm 格式，一个省一个文件下到手机里；渲染引擎在本地矢量绘图，缩放时不重新下载。徒步模式下会显示等高线、山峰高程、小径难度和水源标注，路线规划支持步行、骑行和驾车，导航时语音提示；点一下就能记录 GPS 轨迹，导出 GPX 或 KML；还能导入别人分享的轨迹文件当参考。

生态上它上架了 Google Play、F-Droid 和 App Store，界面自带简体中文，社区在 Telegram 和论坛活跃，2025 年后仍频繁发版；数据随 OSM 每月更新，中国地区的山路数据也在稳步变好。

对 0302 来说它是延伸项目：出发清单手写板旁边可以贴一张二维码，指向常走的三条线的 GPX 文件——日徒步、两日露营、钓鱼。出发前在阁楼里把临安和杭州的离线包下好，把这次的轨迹文件导进 Organic Maps；回来后把记录的轨迹导出 GPX，存到 0802 服务器的装备目录里，和这趟带了哪些装备的清单放在一起。下一次挑背包容量时，看看那条线的爬升和时长就知道该拎 38L 还是 65L。

tumic0/GPXSee ★ 1.2k 无中文 延伸

桌面版 GPS 轨迹查看分析器：支持 GPX、FIT、KML 等十几种格式，在离线地图上叠轨迹，看海拔、速度、心率曲线

→ 装备区攒下的每一条徒步轨迹都需要一个能在电脑上快速回看、对比爬升的工具，GPXSee 轻、快、全离线，比网页服务省心

GPXSee 是捷克开发者 tumic0 用 C++ 和 Qt 写的 GPS 日志查看器，1.2k 星，近六千次提交，Windows、macOS、Linux 都有安装包。它要解决的问题是：手表、手机、运动相机记录的轨迹格式各不相同，想在电脑上离线看一眼、比一比，总得先传到某个网站。GPXSee 双击文件就打开，什么都不上传。

它的工作方式是读文件、画地图、画曲线：支持 GPX、TCX、FIT、KML、IGC、NMEA、GeoJSON 等十几种格式，可以一次拖进几十个文件叠在同一张地图上；地图底图既能用在线瓦片源，也能加载 OziExplorer、MBTiles、GeoTIFF 等离线地图，山里下载好的等高线图也能当底图。下方的图表区画出海拔、速度、心率、踏频、温度和坡度随距离或时间变化的曲线，鼠标在曲线上滑动，地图上的点同步移动；还能给轨迹打点、看统计、导出 PDF 或图片。

生态上它是很多户外论坛推荐的轻量工具，翻译走 Weblate，界面没有中文，但操作简单到不需要说明书；项目持续维护，几乎每月都有版本。

对 0302 来说它是延伸项目：Organic Maps 在山上记的轨迹回家导出 GPX 后，放到 0802 服务器的装备目录里，用 GPXSee 一次把三条常走线全部打开，叠在同一张离线地图上比较爬升和距离。出发清单上每条线旁边写的时长、水量和背包容量，就来自这些曲线；如果某条线的海拔图突然多出一段陡坡，说明该把登山杖挂到出发清单里了。
