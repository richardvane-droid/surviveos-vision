无窗卫生间怎么活？我把整个天花板做成了一块天空

1000W 灯箱 + 六面镜光箱，无窗小间里刷牙也像在露台上晒晨光。

✅ 真实三阶段已完成 #无窗卫生间#酒店感#去家务化#晨间仪式感

📐 它在哪、有多大

地堡东北角的卫生间，≈1.65×1.25m、≈2㎡，北墙和东墙都是外墙但无窗；灯箱嵌在这块小天花板正中，门开向沙发北侧那条走道，南邻储藏室（0210）。

🎬 沉浸式想象

七点整，你推开卫生间的门，天花板那块 1m 见方的灯箱已经提前 5 分钟亮到了“晨浴”档——不是浴霸那种惨白，是被镜面反复弹过之后的软光，从头顶、从两侧镜墙一起包过来，脸上没有一点阴影。淋浴间的雾气往上飘，被光一打像一团发亮的云。你伸手摸墙，暖的——排风在后面轻轻转，镜子一点都不起雾。刷牙的时候你看着镜子里的自己，皮肤居然是有血色的。这个瞬间你会忘了这间 2 平米的小房间连窗都没有。

✅ 设想方案清单

  1. ≈2㎡ 的小卫生间天花板几乎整块嵌 1.0×1.0m 灯箱：1000W 浴霸灯 + 亚克力柔光板，四周留 5cm 出光缝当“天光缝”
  2. 洗手台三面镜 + 顶面镜 + 两侧壁镜，做成六面镜光箱，光被弹到没有死角
  3. 灯箱分三档：晨浴 5000K 全亮 / 日常 4000K 60% / 夜起 2200K 5%，24GHz mmWave 存在感应自动切
  4. 一层原有下水口位置定死，淋浴、洗手盆和 0203 冷凝水都汇到一台小提升泵再进下水，泵藏在马桶后的检修柜里，柜门做磁吸镜面，检修时一拉就开
  5. 镜子背面贴电热除雾膜，跟灯箱联动，开晨浴档就同步加热
  6. 淋浴角顶上再做一块 40×40 小灯箱，跟主灯箱同步，洗澡时头顶也是亮的
  7. 排风扇接 Grove 温湿度模块，湿度 70% 以上自动开，20 分钟后自动停
  8. 1000W 灯箱和吊架那圈黑色阳极氧化铝型材根本不导电，接地要刮漆做接地点或单拉一根接地线

  • “去家务化卫生间”：全部壁挂、零地面杂物，灯光一亮地面干干净净很出片

⚠️ 避坑提醒

  • 1000W 灯箱很热，亚克力板要留散热缝，不然夏天变蒸笼
  • 六面镜好看但清洁量翻倍，水渍一多就变“脏光箱”，除雾膜一定要装
  • 污水提升泵一定留检修口和报警，堵了不是小事

🔧 GitHub 上的成熟方案

按知名度（星数）优先、有中文版优先挑的开源项目，每个都在 2026-09 打开核实过存在。每个方案配一段科普介绍和一张铅笔风的“它怎么工作 + 怎么接进本模块”示意图。

Seeed-Studio/xiao-esphome-projects ★ 37 无中文

Seeed 官方的 XIAO 加 ESPHome 成品工程集：24GHz mmWave 人体存在、MR60BHA2 生命体征、2 路和 6 路继电器、电能计量都有现成 YAML

→ 0805 把全屋 DIY 器件基准定在 XIAO 加 Grove；这里有官方毫米波存在检测和继电器工程，灯箱三档的人体判断和排风扇照它接

xiao-esphome-projects 是矽递科技官方维护的示例仓库，把 XIAO 系列小主控和 ESPHome 之间的接法写成一份份可以直接抄的工程。它解决的是一个很实际的麻烦：XIAO 型号多、引脚各不相同，某个模块到底怎么在 YAML 里声明，官方说明散在 Wiki 各处，这里把常见场景收成完整配置。

每个工程是一个目录，一份 YAML 加一段说明：选哪块 XIAO、接什么模块、接哪几个脚、刷完之后 Home Assistant 里会冒出哪些实体。现有工程覆盖电能计量、土壤湿度、IoT 按钮、24GHz mmWave 人体存在、MR60BHA2 生命体征与跌倒检测、W5500 以太网，以及 2 路和 6 路继电器。固件跑在板子本地，判断和计时都不过服务器，断网照常工作，HA 只负责记录和推送。

仓库说明是英文，但每块板子和每个模块在 Seeed Wiki 上都有中文页，照着看不吃力；更新跟着 ESPHome 版本走。

卫生间这边用它两处。三档光切换的人体判断换成官方毫米波工程：MR60BHA2 装在灯箱边沿朝下，静止站着洗澡也不会丢人，YAML 直接抄，实体进 HA 之后按时段选场景。排风扇照它的 2 路继电器工程接，湿度由 Grove 温湿度模块给，超 70% 开、20 分钟到或降回 60% 停，全在板子本地跑。坑是雷达别正对淋浴水流，水幕会被当成动作。

wled/WLED ★ 18.7k 无中文

ESP32 上最流行的灯带控制固件，网页和 App 直接控，支持 RGB+CCT 灯带、250 个预设、定时和 HomeAssistant 自动发现

→ 灯箱四周 5cm 天光缝和镜子暖光灯带直接刷它，晨浴 / 日常 / 夜起三档存成预设，HA 里一键切

WLED 是奥地利开发者 Aircoookie 在 2016 年开始写的 ESP32 / ESP8266 灯带固件，18.7k 星，是 GitHub 上最流行的灯光固件，没有之一。它解决的问题是：一根几十块钱的灯带接一块 ESP32，刷完固件就是一盏能手机调、能被家庭自动化接管的智能灯，不用写代码。

固件内置网页服务器：手机打开网页就能选颜色、调亮度、挑一百多种效果，把状态存成预设，最多 250 个；内置定时器按时间或日出日落调预设。对外它同时开放 JSON 和 MQTT 接口，Home Assistant 有官方集成，自动发现后每个 WLED 设备就是一个灯实体，预设也能当选项切换。支持单色、CCT 双色温、RGB、RGBW 各种灯带，可分段控制，还能收 DDP、E1.31 协议做同步。

社区极大；文档站只有英文，但中文教程和 B 站视频非常多，淘宝能买到预刷固件的控制器。

在 0202 里它管两处灯：灯箱四周那圈 5cm 天光缝里的 CCT 灯带，以及六面镜光箱边缘的暖光灯带。把晨浴 5000K 全亮、日常 4000K 六成、夜起 2200K 5% 存成三个预设，HA 收到人体感应后按时段切预设，晨浴档同时拉起除雾膜的继电器。坑在于浴室潮湿，控制器要装在灯箱上方干燥腔体里，灯带选 IP65 硅胶套管的，电源按每米功率留三成余量。

basnijholt/adaptive-lighting ★ 3.4k 无中文

HomeAssistant 自定义组件，按太阳位置自动调整灯光色温和亮度，自带睡眠模式和手动接管检测

→ 和 0201 共用一份时间表，卫生间灯箱早上 5000K、夜起 2200K 不用再单独写自动化，夜里靠 sleep mode 一律最暗最暖

Adaptive Lighting 是荷兰开发者 Bas Nijholt 写的 Home Assistant 自定义组件，3.4k 星，HA 社区里做“灯光跟着太阳走”最常用的方案。它让每一盏能调色温的灯按当地日出日落曲线自动变化，早上暖、中午白、傍晚回暖，晚上降到最暗最暖，让室内作息跟着太阳走。

它不控制硬件，只算值：读取 HA 的经纬度和时间，求出太阳高度角，映射成色温和亮度百分比，再定时调用灯的开灯服务写进去。手动改了灯，它会识别出“不是 HA 做的改动”并暂停接管，直到灯关掉再开；sleep mode 开关一打开，所有灯降到设定的最低亮度和最暖色温。色温上下限、过渡秒数都能按灯组单独配。

它走 HACS 安装，兼容 HA 里所有灯实体，包括 WLED 和 ESPHome 的 CCT 灯；文档英文，HA 中文社区配置分享很多。

在 0202 里它是把卫生间和地堡主空间“调成同一个时区”的那根线：灯箱的主灯和 WLED 灯带都挂进同一个 Adaptive Lighting 开关组，早上的 5000K 晨浴和傍晚的暖光自动跟 0201 的模拟阳光同步，而不是各写各的时间表。夜起 2200K 5% 直接用它的 sleep mode，睡前 0201 进入落日时同步打开，半夜进卫生间就只有一点暖光。注意感应开灯要给两秒过渡，否则会先闪白光再变暖；不能调色温的浴霸灯就只让它管亮度。

patrickcollins12/esphome-fan-controller ★ 741 无中文

ESP32 加温度探头做 PID 调速风扇的 ESPHome 方案，配完整教程、接线图和 HA 仪表盘上在线调参

→ 把温度探头换成湿度探头，就是湿度 70% 自动开、20 分钟后自动停的排风控制器，阈值和计时全在 ESP32 本地跑

esphome-fan-controller 是澳大利亚开发者 Patrick Collins 开源的一个 ESPHome 项目，741 星，原本是为了给电视柜里发热的机顶盒做一个“会自己调速的静音风扇”。它的价值在于把一个小硬件项目讲透了：一块 ESP32、一颗 DHT11 探头、一只 12V 四线 PWM 风扇和降压模块，接线图、YAML、PID 调参全写成教程，很多人的第一个 ESPHome 硬件就是照它做的。

原理是把传感器读数喂给 ESPHome 内置的 PID 组件：设一个目标温度，PID 算出风扇该转多快，输出成 PWM 占空比；转速、目标值、PID 参数都暴露成 HA 实体，仪表盘上边看曲线边调，也能手动接管。逻辑全在 ESP32 本地，断网照样工作。

项目是英文的，但全是 ESPHome 标准组件，中文 ESPHome 教程都能对上；更新不勤，也没什么要更新的。

在 0202 里它变成排风扇控制器：把 DHT11 换成更准的 SHT31 湿度探头，风扇换成管道排风机（用继电器或调速模块），控制逻辑不用 PID，改成 ESPHome 的阈值加计时器——湿度超过 70% 开机，跌回 60% 以下或满 20 分钟停机，探头和 ESP32 装在灯箱上方的干燥腔里，只把探头伸进浴室。坑是水汽会让探头读数飘，探头别贴淋浴角顶；HA 里加一条兜底：连续开机超过一小时就推送提醒。

homebridge/homebridge ★ 25.5k 界面有中文 延伸

Node.js 写的 HomeKit 桥：通过两千多个插件把非 HomeKit 设备接进苹果家庭 App，Siri 和 iPhone 控制中心直接用

→ 卫生间灯箱三档和除雾膜想在 iPhone 锁屏和 Siri 上一句话切，Homebridge 是把 HA 和自制设备塞进苹果家庭最省事的桥

Homebridge 是 Nick Farina 在 2015 年发起的 Node.js 项目，25.5k 星，口号是给等不及的人的 HomeKit 支持。它要解决的问题是：苹果家庭 App 和 Siri 体验好，但认证的 HomeKit 设备少而且贵；Homebridge 用软件模拟一个 HomeKit 配件桥，把任何设备伪装成苹果认识的配件。

它的架构是核心加插件：核心实现 HAP 协议，在局域网里用 mDNS 广播自己，iPhone 扫一个二维码就把桥加进家庭 App；每个插件对应一种设备或平台，把设备状态映射成 HomeKit 的服务和特征。插件用 npm 装，现在有两千多个，从米家、涂鸦到 MQTT、HTTP 万能插件；官方 UI 是一个网页，装插件、改配置、看日志都在里面。

生态庞大且活跃，2025 年后核心和 UI 持续更新，UI 有简体中文，中文教程在 NAS 和智能家居社区非常多。

对 0202 它是延伸的入口：卫生间的灯箱三档、镜子除雾膜、排风扇本来都在 HomeAssistant 里，再通过 Homebridge 的 MQTT 插件暴露成 HomeKit 配件，iPhone 锁屏就多了一个晨浴按钮，Siri 一句晨浴就把灯箱、除雾膜和小灯箱一起打开；人体感应的夜起档留在 HA 自动化里不动。注意一个设备只从一条路进家庭 App，HA 自带的 HomeKit 集成能做的就不重复用 Homebridge，它更适合接 HA 没有的小众设备。

music-assistant/server ★ 3.1k 界面有中文 延伸

Home Assistant 生态的音乐库与播放器管理器：接本地库和流媒体服务，推到 Sonos、AirPlay、Chromecast、Snapcast 等播放器

→ 早上进卫生间刷牙那五分钟想有歌，让灯箱切晨浴档的同时把歌推到卫生间的小音箱，Music Assistant 就是 HA 里的那个点播台

Music Assistant 是 Marcel van der Veldt 发起、现在由 Open Home Foundation 支持的开源音乐服务器，Python 写成，3.1k 星，定位是 Home Assistant 的音乐大脑。它要解决的问题是：音乐在网易云、Spotify、本地 NAS 各处，播放器有 Sonos、AirPlay、小音箱各种牌子，缺一个把音源和播放器统一起来、还能被自动化调用的中间层。

它的架构是音源提供者加播放器提供者：音源端接本地文件库、Spotify、Tidal、Subsonic 服务器（比如 Navidrome）和网络电台；播放器端接 Sonos、AirPlay、Chromecast、Snapcast 和 HA 的媒体播放器。中间它维护统一的音乐库和播放队列，能把不同音源的曲子混排、在不同播放器之间同步分组。它以 HA 加载项一键装，装好后 HA 里多出一个 mass 域，自动化里一句 play_media 就能点歌。

社区活跃，2025 年后版本很密，界面翻译含简体中文，中文教程主要在 HA 玩家圈。

对 0202 它是延伸的小享受：卫生间天花板灯箱旁边塞一只小 AirPlay 或 Snapcast 音箱，人体感应触发晨浴档时，HA 自动化顺手叫 Music Assistant 把早间歌单推到卫生间播放器，洗完澡后排风停的时候把歌停掉；夜起档则永远静音。注意卫生间潮，音箱选 IP 等级高的，别放淋浴角正上方。
