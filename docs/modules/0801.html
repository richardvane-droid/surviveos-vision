📐 它在哪、有多大

它不属于哪一间屋：物品分散在阁楼、储藏室、木屋、庭院的箱子和货架上，数据层跑在地堡储藏室的小主机里。入口有两个——储藏室门边墙上的 12.9 寸平板（紧邻 0802 屏墙南端），以及手机上的同一套界面。真实项目 2026-09 已进入需求收集：拍照/视频识别、品牌型号 + 估值提取、房间归类、全屋搜索、六个电商平台订单半自动盘点。（0008 未定位，设想落位）

🎬 沉浸式想象

你想找那把去年买的鱼钩钳。以前要翻三个柜子，现在你对着地堡储藏室门边那块平板说了一声“鱼钩钳”，屏幕上的等距全屋地图亮起一个小点：阁楼间 0302，第三个灰色箱子，B 层。地图旁边是那个箱子的照片，你能看到钳子躺在一卷鱼线旁边。走到阁楼，箱子侧面的二维码贴纸下面还有一行手写的英文名，你扫了一下，平板上那个小点从“在库”变成“外借中”。晚上放回去再扫一下，它就回家了。整套系统跑在地堡的 HomeAssistant 里，没有云。

✅ 设想方案清单

  1. 全屋统一用同一款透明收纳箱（40×30×24cm），每箱侧面贴一张防水二维码 + 手写标签
  2. 地堡储藏室门边的隔墙上挂一块 12.9 寸平板，显示 7 个区域的等距地图，每件物品都是地图上一个点
  3. 每箱拍一张俯视照片存进系统，扫码直接看照片，不用开箱
  4. 拿走 / 放回各扫一次，状态自动切换，超过 7 天没归还就推送提醒
  5. PSK 生存盒的零件也建档，做盒子时清单直接生成采购单
  6. 数据本地存在储藏室里的小主机上，跟 0802 大屏共享一份数据库
  7. 每季度一次“盘点日”，用平板批量扫码对账，顺便清理不用的东西

🔥 小红书灵感点

  • “透明收纳 + 手写标签”的小红书经典组合，加个二维码就是数字版
  • “全屋等距地图”插画风：把自己家画成游戏地图，找东西像开宝箱
  • “去家务化”的终极形态：不是收纳得好看，是永远不用找东西

⚠️ 避坑提醒

  • 建档最累的是第一次，一次别贪多，一个区域一个周末，不然半路放弃
  • 二维码一定要防水防潮，普通打印纸在地堡一个月就糊
  • 别为了好看用不透明箱，看不见东西的箱子迟早变“黑洞”

sysadminsmedia/homebox ★ 7.1k 界面有中文

面向家庭用户的自托管物品库存系统，支持嵌套位置、标签、照片附件和二维码标签打印

→ 每个收纳箱一个二维码、扫码看箱内照片和清单，它就是照这个需求做的，Go 单文件部署，小主机跑得动

Homebox 是一套专为家庭用户设计的自托管物品库存系统，由 sysadminsmedia 社区维护，Go 写成，单个二进制加一个 SQLite 文件就能跑，闲置内存不到 50MB。它要解决的问题很朴素：家里几百上千件东西，到底在哪个箱子里。

它的数据模型只有三层：位置可以嵌套，比如阁楼间→第三个灰箱→B 层；物品挂在位置下，可以传照片、附购买凭证和保修单、记维修记录；标签横向打标。核心功能是标签生成器：给任意位置或物品批量出带二维码的标签纸，扫码直接跳到那一页，附带的照片和清单一眼看完。还有全文搜索、自定义字段、CSV 导入导出、多用户、REST API，Docker 一行部署。

社区活跃，2025 年后持续发版，界面通过 Weblate 有简体中文翻译，但 README 和文档只有英文。

在 0801 里它就是那份箱子数据库：全屋七个区域建成顶层位置，每个透明收纳箱一个子位置，标签生成器出防水二维码贴纸，俯视照片传到位置的附件里，扫码看图不开箱。找东西走它的搜索 API，HomeAssistant Assist 把语音转成文字后调 API 拿到位置，再在平板的等距地图上点亮那个点。要注意它本身没有借还状态，得靠自定义字段加 HA 自动化来补；另外照片别传原图，先压到 1MB 以内，不然 SQLite 很快就胖。

inventree/InvenTree ★ 7.3k 界面有中文

开源库存管理系统，零件、库存、BOM、供应商和采购单一条链路，带标签打印和手机端

→ PSK 生存盒的零件建档和一键生成采购单，用它的 BOM 和最低库存告警正合适

InvenTree 是一套开源的库存管理系统，Python/Django 后端加 React 前端，主要面向电子工作坊和小型制造：零件建档、库存出入、BOM（物料清单）、供应商与采购单，一条链路全包。它解决的是做一件东西要买什么、库里还有多少这个问题，而不是家里的日用品在哪。

它的核心是零件与库存项分离：零件是 M3×8 内六角螺丝这个概念，库存项是某个抽屉里那一袋 200 颗。给一个成品零件挂一份 BOM，系统就能算出按库存能做几套、缺什么，一键生成采购单发给绑定的供应商。还有条码和二维码标签打印、最低库存告警、插件系统、REST API 和 Android/iOS 手机端。2026 年 7 月发布 1.4.1，累计 157 个版本，社区非常活跃；界面通过 Crowdin 有简体中文，文档站英文为主。

在 0801 里它只负责一小块：PSK 生存盒和各模块的零件建档。把每个盒子做成一个带 BOM 的成品零件，螺丝、电池、鱼钩这些消耗品设最低库存，做盒子前看一眼缺件清单，直接出采购单。它和 Homebox 分工明确：Homebox 管东西在哪个箱，InvenTree 管零件还剩多少、要买多少，两边用同一个二维码前缀区分。别把家里的日用品也塞进来，那会把它变成一个很重的表格。

snipe/snipe-it ★ 14.9k 界面有中文

开源 IT 资产管理系统，借出归还记录、资产标签、到期提醒、审计盘点和 REST API

→ 拿走扫码变外借、放回扫码变在库，超 7 天未还推送，这套 checkout / checkin 流程它最成熟

Snipe-IT 是一套开源的 IT 资产管理系统，Laravel 12 写成，14.9k 星，是这个品类里最知名的自托管方案，本来是给公司管笔记本、显示器和软件许可证用的。它解决的核心问题只有一个：这件东西现在在谁手里、什么时候该还。

它的模型是资产加用户加借出记录：每件资产有资产标签和二维码，扫码打开就是借出和归还两个按钮，借出时可以设预计归还日，到期系统自动发提醒；还有位置、状态标签（在库、外借、维修、报废）、维护记录、审计模式（批量扫码盘点）和一套完整的 JSON REST API，通知支持邮件、Slack 和 Webhook。项目十年不辍，每周都有提交，331 位贡献者；界面通过 Crowdin 有简体中文，文档只有英文。

在 0801 里它承担借还这条流程：鱼钩钳这类会被带出屋的工具，在它里面登记为资产，拿走扫码借出、放回扫码归还，超过 7 天未还由它的到期提醒经 Webhook 推到 HomeAssistant 再转手机；每季度的盘点日用它的审计模式，平板批量扫码对账。它比 Homebox 重得多（PHP 加 MySQL），所以只把会外借的几十件工具放进来，日常收纳箱不建档，两个系统靠同一套二维码前缀区分，扫码时由 HA 判断该跳哪一边。

teableio/teable ★ 21.7k 界面有中文 延伸

开源的多维表格 / AI 电子表格，Airtable 的自托管替代：每张表就是一张真正的 PostgreSQL 表，百万行不卡，带看板、画廊、表单等视图

→ 真实项目要记品牌型号、估值、电商订单号，字段随时增减；专门的物品库软件改不动表结构，用多维表格当物品总账最灵活

Teable 是一个中国团队做的开源多维表格，21.7k 星，定位是 Airtable 的自托管替代，最近又加上了 AI 生成字段与自动化。它解决的问题很朴素：想要一张能随时加列、能挂附件、能被程序读写的表，又不想把数据放到别人的云上。

它的底层就是 PostgreSQL：每张表对应一张真实的 Postgres 表，字段直接映射成列，百万行也能正常筛选排序，任何 SQL 工具都能直接连上去查。上层是 NestJS 服务加 React 前端，提供网格、看板、画廊、日历、表单五种视图，字段支持公式、关联、附件、条码，改动经 WebSocket 实时推送。对外有 REST API、Webhook 和自动化，Docker Compose 一条命令部署。

它由国内开发者主导，界面自带中文，文档站有中文版，2026 年仍在密集发版；比 NocoDB 视图更完整，对自托管足够。

在 0801 里它是延伸：Homebox 管箱子和位置树没问题，但真实项目 2026-09 收集的需求里还有品牌型号、估值提取、六个电商平台的订单半自动盘点，这些字段一直在变。做法是在 0804 的笔记本上跑 Teable，建一张物品总表，列是名称、品牌型号、估值、房间、箱号、俯视照片、购买平台、订单号、状态；各平台订单导出 CSV 后导入，画廊视图按照片翻，看板按房间分列，表单视图在扫码后填拿走或放回。底层是 Postgres，0802 的平板地图直接读同一个库，不用再同步。

zxing-js/library ★ 2.9k 无中文 延伸

ZXing 条码库的 TypeScript 移植：浏览器里直接调摄像头解二维码与 EAN、Code128 等一维码，不用装 App

→ 平板和手机用的是同一套网页界面，扫码就得在浏览器里完成；它是网页扫码里最老牌、格式最全的库，商品条码也能解

zxing-js/library 是 Google 老牌条码库 ZXing 的 TypeScript 移植，2.9k 星，把一维码和二维码的解码算法搬进了浏览器。它解决的问题是：想在网页里扫码，又不想让用户装 App，也不想把摄像头画面传到服务器上识别。

它的工作方式是纯前端的：用 getUserMedia 打开摄像头，每隔几十毫秒抓一帧到 canvas，转成灰度位图交给解码器，解出来就回调一段文本。BrowserMultiFormatReader 会同时尝试 QR、Data Matrix、EAN-13、Code128 等十几种格式，也可以指定只解某一种来提速；除了视频流，也能对图片文件解码。

它的状态要说清楚：README 明确写着项目处于维护模式，只接受补丁，作者在找新维护者。但它的 npm 下载量仍然很高，Vue、React 的扫码组件大多包着它；浏览器原生的 BarcodeDetector 是备选，只是 iOS Safari 支持一直不稳。中文资料主要是博客里的接入教程。

在 0801 里它是延伸：方案里的扫码目前依赖平板自带相机，扫完再跳网页。用它做一个扫码页嵌进 HA 仪表盘的网页卡，平板和手机打开同一个地址就能扫：扫箱侧二维码跳到 Homebox 的箱子页并切换在库或外借，扫商品包装上的 EAN 条码则查公开商品库自动填品牌型号，盘点日开连续扫码模式对账。注意浏览器只在 HTTPS 下开放摄像头，小主机上得配一个内网证书。

pmndrs/react-three-fiber ★ 31.9k 无中文 延伸

three.js 的 React 渲染器：把 3D 场景写成组件，状态一变画面自动更新；配 drei 工具库几十行就能转着看一个 glTF 模型

→ 平板上的等距地图和 PSK 生存盒的零件清单都可以做成能转的 3D 视图，用 React 写比裸写 three.js 省一半代码

react-three-fiber 是 pmndrs 社区维护的 three.js 的 React 渲染器，31.9k 星。它解决的问题是：three.js 是命令式的，建网格、加场景、每帧更新都要手写；它把每个 three.js 对象变成一个 JSX 组件，状态一变画面跟着变。

它是一个自定义 React 渲染器：Canvas 组件创建 WebGL 上下文和渲染循环，里面的 mesh、boxGeometry、meshStandardMaterial 这些标签被翻译成对应的 three.js 对象，属性直接映射；useFrame 让组件参与每一帧更新，useLoader 负责加载 glTF 模型和贴图。配套的 drei 库提供轨道控制器、环境光、标注等现成组件，几十行代码就能让模型转起来。

它是 React 生态里做 3D 的事实标准，2026 年 v9 版跟上了 React 19；没有官方中文文档，但掘金和 B 站教程不少。

在 0801 里它是延伸：等距地图先用 SVG 做，够用；稳定之后可以做一个 3D 版本，每只透明收纳箱是一个 Box 组件，颜色由 HA 里的实体状态驱动，在库灰色、外借橙色，点一下箱子相机飞过去并弹出俯视照片；PSK 生存盒则把 glTF 模型加载进来，边转边看每个零件对应清单里的哪一行，缺件半透明。数据从 HA 的 WebSocket 订阅，页面仍嵌在 HA 仪表盘里。
