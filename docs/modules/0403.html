阁楼仓库 · 模块 0403 · 喷涂柜

被问爆了！1.5 米宽的喷涂柜怎么做到零粉尘零异味

木工间东缘一只下抽式喷涂柜，一根直管排风出东墙，喷完的木盒排队晾在杆上，像小型画廊。

⬜ 真实项目待设计 #通风系统#手作#喷涂柜#喷漆#PSK

📐 它在哪、有多大

不是独立房间，是一只 ≈1.5×1.0m 的下抽式喷涂柜，放在 0404 木工间可站立核心的东缘南段；排风管向东穿过 2m 低矮圈出东墙，≈2.06m 一根直管不拐弯；离北段的台锯 5m 以上。

🎬 沉浸式想象

你戴上半面罩，走到木工间东边斜顶下那只喷涂柜前，按下柜灯，柜底的风机先转起来，柜角的橙色灯亮了。柜子 1.5 米宽、1 米深，台面是一层格栅，风往下抽，手里的 PSK 盒子喷出去的雾一点都不飘回来，直接被格栅吞掉，顺着那根 2 米长的直管排出东墙。转盘一转，四面刷匀。喷完挂到柜顶那根不锈钢晾杆，旁边已经挂着三只昨天喷的哑光黑，像一排等着领养的小猫。你拉下柜前的透明卷帘，它们安静地干燥，5 米外的台锯边闻不到一点味。手机上 HomeAssistant 显示：喷涂柜 VOC 正常，排风还剩 20 分钟。

✅ 设想方案清单

  1. 用 30 铝型材 + 镀锌板做一只 1.5×1.0m 下抽式喷涂柜，台面是可拆格栅，格栅下是过滤棉和集雾盘
  2. 柜底接 300m³/h 管道风机，150mm 直管向东穿低矮圈出东墙，全长约 2.06m 一根到底不拐弯，外墙口带防雨百叶
  3. 枪钩联动：喷枪从挂钩上拿起风机自动启动，挂回后延时 30 分钟再停，用 ESPHome 做
  4. 台面放一个带脚轮的喷漆转盘，脚踩也能转，四面不用挪工件
  5. 柜顶横一根不锈钢晾杆 + S 钩，能挂 10 件小件，下面垫一次性牛皮纸接滴
  6. 柜前挂一幅透明 PVC 卷帘，喷完拉下当干燥柜；柜角一盏橙色“喷涂中”灯，提醒自己别在旁边开台锯
  7. 柜位在木工间南段、离台锯 5 米以上，留一个 VOC 传感器接 HomeAssistant，超标手机推送提醒开天窗

⚠️ 避坑提醒

  • 排风别只靠开天窗，格栅下负压不够雾会飘回木工间，板子上全是漆点
  • 风机要选防爆或至少远离电机火花，溶剂雾在密闭空间是真的危险
  • 过滤棉要有备用，堵了风量掉一半自己感觉不到，每月换一次别偷懒

esphome/esphome ★ 11.7k 无中文（社区教程多）

用 YAML 配置文件给 ESP32 生成固件的开源系统，传感器、继电器、风扇原生接入 Home Assistant

→ 喷涂柜的枪钩联锁、延时停机、VOC 告警本质上就是一块 ESP32 上的几段 YAML，不用写一行 C；本模块唯一的通用平台

ESPHome 是 Nabu Casa（Home Assistant 背后的公司）维护的开源固件生成系统，11.7k 星。想让一块 ESP32 读传感器、控继电器、驱动风扇并接进 Home Assistant，传统做法要写 C++ 和 MQTT，而它只需要写一份 YAML。

原理是：YAML 里声明板子、Wi‑Fi、组件（sensor、binary_sensor、fan、switch、script）和引脚，ESPHome 把它编译成完整固件，第一次 USB 刷入，以后走 OTA。运行时设备通过原生 API 和 HA 直连，每个组件自动变成一个实体；YAML 里的 on_press、delay、lambda 能写设备本地的逻辑，Wi‑Fi 断了也照常执行。组件库上千个，风扇 PWM、SGP41 的 VOC 指数、PMS5003 颗粒物、微动开关都是现成的。文档是英文，但中文社区极其活跃，B 站教程很多。

在 0403 里，一块 ESP32 就是整个喷涂柜的控制器：枪钩上的微动开关是 binary_sensor，拿起枪触发风机继电器和橙色灯，挂回去启动一个 30 分钟延时脚本再停；SGP41 的 VOC 指数超阈值时本地直接开风机，同时推给 HA 发手机提醒；柜灯也挂进来。坑是喷漆雾会糊传感器，VOC 探头装在柜外进风侧而不是格栅下。

patrickcollins12/esphome-fan-controller ★ 741 无中文

ESP32 加 ESPHome 做的 PID 温控风扇控制器，接 HomeAssistant 手动或自动调速

→ 排风机联动的 ESPHome 逻辑照它改：门开启动、延时 30 分钟停，再加个 VOC 阈值触发

esphome-fan-controller 是澳大利亚开发者 Patrick Collins 做的 ESPHome 风扇控制器，741 星，原本是给电视柜和网络机柜做的安静恒温风扇，价值在于把 PWM 调 4 针风扇、PID 温控、Home Assistant 面板三件事写成了一份可以直接抄的 YAML，是社区做智能风扇的标准参考。

它的原理是：ESP32 一个引脚输出 25kHz PWM 信号接到 12V 四针风扇的调速线，另一个引脚读风扇的转速反馈脉冲，DHT 或其他温度传感器读环境温度，PID climate 组件按目标温度和当前温度算出占空比，温度越高转越快。目标温度、Kp、Ki、Kd、手动转速都暴露成 HA 实体，在面板上调，不用重新刷固件；Wi‑Fi 断了也能独立运行。硬件只有 ESP32、风扇、LM2596 降压模块和 12V 电源。

仓库有详细接线图和调参说明，没有中文，但 HA 中文社区有不少照它做的帖子。

在 0403 里，它的 PID 部分不用，要抄的是 fan 组件、转速反馈和 HA 面板那套骨架：把温度输入换成枪钩微动开关和 VOC 指数，用 script 写延时停机，风机换成 300 立方米每小时的管道风机走继电器或 EC 风机的 0–10V 调速。坑是管道风机大多不是 4 针 PWM，先确认调速接口再定电路。

MallocArray/airgradient_esphome ★ 332 无中文

AirGradient 空气质量监测器的 ESPHome 配置，PM2.5、CO2、TVOC 一起上报 HomeAssistant

→ 喷漆间的 VOC 传感器直接抄它的 SGP41 配置，超标推送提醒的传感器部分就搞定了

airgradient_esphome 是 MallocArray 维护的一套 ESPHome 配置，332 星，2026 年 6 月还在更新，目标是让 AirGradient 这家开源硬件公司的空气监测器不用官方固件也能跑，并保留它们的传感器校准成果。AirGradient 的板子是公开设计的，能自己焊，这套 YAML 把每个传感器的读法和补偿都写好了。

做法是 ESPHome 的 packages 机制：每种板子一个主 YAML，引用若干功能包，每个包对应一个传感器：PMS5003 的颗粒物，SenseAir S8 的二氧化碳，SGP41 的 VOC 与 NOx 指数（走 Sensirion 的气体指数算法，输出 1 到 500 的相对值），SHT40 的温湿度，再加上 OLED 等包。自己的 YAML 里引用仓库地址和需要的包、改 Wi‑Fi 即可，读数通过原生 API 进 Home Assistant。

没有中文文档，但传感器在国内都容易买，接线和 ESPHome 中文教程通用。

在 0403 里，只取它的 SGP41 包：接在喷涂柜的 ESP32 上，VOC 指数是相对基线的数值，喷漆一开始就会冲到 300 以上，这个跳变本身就是告警信号，阈值设 250 左右。坑是 SGP41 需要通电预热并学习基线 12 小时以上，刚装上的头一天数据不能当真。

comfyanonymous/ComfyUI ★ 133k 无中文（社区教程多） 延伸

节点式的 AI 图像与视频生成引擎：把 Stable Diffusion、Flux 等模型拆成可拖连的节点图，本地显卡跑，工作流可存可分享

→ 喷涂之前先看效果：把 PSK 盒子的照片喂进 ComfyUI，用图生图和 ControlNet 生成哑光黑、军绿、做旧铜的几种涂装预览，再决定开枪

ComfyUI 是开发者 comfyanonymous 发起、现在由 Comfy Org 团队维护的开源 AI 生成引擎，用 Python 写成，133k 星，是本地跑扩散模型最主流的界面。它要解决的问题：扩散模型的推理是一串可拆开的步骤，一体化界面把它们藏起来，ComfyUI 把每一步做成节点让用户自己连。

它的工作方式是节点图：加载模型、编码提示词、采样、解码、保存图片各是一个节点，用连线把它们串成工作流，点一下运行，引擎只重新计算变化了的部分，显存管理做得很精细，8GB 显卡也能跑大模型。图生图、局部重绘、ControlNet 控线稿、IP-Adapter 参考风格，以及后来的视频模型都以节点形式加入，工作流保存成 JSON 或直接嵌在输出图片里，别人拖进去就能复现。

生态上自定义节点有几千个，模型来自 Hugging Face 和 Civitai；官方 README 只有英文，但国内 B 站、知乎的 ComfyUI 教程数量惊人，还有多个中文汉化插件。项目每周一固定发版。

对 0403 来说它是延伸项目：喷涂柜是一次性的——喷错颜色就得打磨重来。开枪之前，把 PSK 盒子或木盒的照片放进 ComfyUI，用 ControlNet 的 Canny 或深度节点锁住外形，提示词换成哑光黑、军绿、做旧黄铜、透明清漆，几分钟出四张预览，挂到 0802 中枢屏上比一比再决定调哪罐漆。跑在 0802 服务器的显卡上，工作流存成一个涂装预览的 JSON，下次换个物件只要换一张照片。

google/filament ★ 20.4k 无中文 延伸

Google 的实时物理渲染引擎：跨平台 PBR，金属度、粗糙度、清漆层等材质模型一应俱全，附带一份业界公认的 PBR 教科书文档

→ 喷涂柜里的哑光、缎光、高光、清漆其实就是 PBR 里的粗糙度和清漆层参数，用 Filament 在网页里实时转着看，比生成图更能表达质感

Filament 是 Google 维护的开源实时物理渲染引擎，用 C++ 写成，20.4k 星，桌面、手机和浏览器 WebAssembly 都能跑，Android 的场景查看器用的就是它。它要解决的问题：在手机级算力上用符合物理的方式把金属、木头、清漆在任何光照下画对。

它的工作方式是 PBR 管线：材质文件里写基础色、金属度、粗糙度、反射率，再加清漆层、各向异性等可选模型；灯光支持方向光、点光和基于图像的环境光，引擎按物理光照方程实时算每个像素。工具链把 glTF 模型和 HDR 贴图转成引擎格式，gltf_viewer 拖进模型直接看，JavaScript 绑定能嵌进网页。它的文档《Physically Based Rendering in Filament》被业界当 PBR 教材读。

生态上它是 Google 官方项目，每月更新；没有中文文档，但那份 PBR 文档有民间中文翻译。

对 0403 来说它是延伸项目：ComfyUI 出的预览是像素的想象，Filament 出的是参数的推演。把 PSK 盒子的 STEP 模型从 0204 设计台导成 glTF，在 gltf_viewer 里把粗糙度从 0.2 拉到 0.8，看哑光和高光的差别，再打开清漆层看喷完清漆是什么效果；用一张阁楼天窗下拍的 HDR 做环境光，预览就是这只盒子在这间屋里的样子。把网页版嵌进 0802 中枢，喷涂柜旁的平板上转着看，粗糙度对应的漆型号写在旁边。
