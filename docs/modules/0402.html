阁楼仓库 · 模块 0402 · 材料仓库

码住！25 平米矮矮的材料仓库装下我三年的木头、板材和半成品

斜顶下一排 7 米长的木料货架、一溜标签收纳箱，每根木头都知道自己是哪年买的。

⬜ 真实项目待设计 #收纳系统#标签控#原木风#数字孪生#防潮

📐 它在哪、有多大

阁楼北条，≈7.5×3.3m，24.8㎡，北墙长 12.6m；靠外的低矮带（净高 0→2060 渐变）放长直货架和板材，靠内 1.24m 站立带是取货通道；东端接 0404 木工间，南边隔断后是 0401 过道和楼梯。

位置与尺寸依据 0008 户型图与空间标注 v1；≈ 为按图面比例预估、未实测。看户型图 →

🎬 沉浸式想象

周六上午，你弯腰钻进北条的斜顶下，头灯照在那排顺着屋面躺着的木料上，松木、橡木、胡桃木按颜色从浅到深排成一道渐变。你退回 1.2 米宽的站立带，手机扫一下箱子上的二维码，屏幕跳出来“黄铜配件 · 23 件 · 上次使用 6 月 3 日”。矮货架第二层是透明塑料周转箱，里面的 3D 打印线材、皮革边角、帆布卷一格一格分明。尽头有一台小除湿机低声嗡嗡，湿度表指在 52%。你把 A 字架拉出来，抽出一块 18mm 桦木多层板，架上立刻空出一个洞，像书架少了一本书。这里没有“找找看”，只有“第三排左二”。

✅ 设想方案清单

  1. 顺着北墙做一排 7 米长的长直木料架，随斜顶分三阶，方料顺长躺着放，每格贴木种 + 厚度标签
  2. 低矮带里放 2 层矮重型货架（每层承重 200kg，最高不过 1.2m），下层放板材边角，上层放轻的周转箱
  3. 统一用同一款透明周转箱，箱口贴打印标签 + 二维码，扫码跳到 0801 数字孪生库
  4. 板材靠在带脚轮的 A 字架上（高 1.2m），推到站立带选料，推回斜顶下停，不占通道
  5. 货架尽头挂一个温湿度传感器（ESPHome），湿度超 65% 自动开除湿机
  6. 楼梯口这头留一格“半成品暂存区”，没做完的项目连零件一起装箱贴日期，不散
  7. 地面沿站立带画一条黄色胶带线，线内 1.2 米是通道，箱子不许过线，永远能走到底

🔥 小红书灵感点

  • “物品数字孪生”话题：每箱贴二维码，手机扫一下就知道里面有什么，仓库变成可搜索的

⚠️ 避坑提醒

  • 板材千万别直接平放在地上，杭州梅雨天一周就吸潮翘边，架起来离地是底线
  • 货架别贪高，斜顶下最高就 1.2 米，塞满会拿不出来，久了就变成永远不碰的死角
  • 周转箱别买杂牌，尺寸对不上叠不起来，两年后一柜子歪歪扭扭

inventree/InvenTree ★ 7.3k 界面有中文

开源零件库存管理系统，Django 后端，支持条码、库位、BOM 和手机 App

→ 黄铜配件、螺丝五金这种按数量管的小零件用它更合适，出入库有条码扫描

InvenTree 是澳大利亚工程师 Oliver Walters 发起的开源零件库存管理系统，7.3k 星，2026 年 7 月发布 1.4.1 版，最初是给电子和机械小作坊管理元器件的，现在很多创客空间和小工厂都在用。它解决的问题是按数量管的小零件：黄铜配件、螺丝五金、电子模块，进多少、用多少、还剩多少、放在哪个格子，以及一个项目要用到哪些件。

它的架构是 Django 后端加 React 前端，数据库可选 SQLite、PostgreSQL、MySQL，用 Docker 一条命令部署。核心数据模型是零件、库存项、库位和供应商：零件是抽象的型号，库存项是某一批实物，库位是一棵树，从仓库到货架到箱子再到格子；条码和二维码是它的强项，每个库位和库存项都能生成码，手机 App 扫码就能出入库、盘点、移库，还支持 BOM 物料清单和采购单。插件系统可以接标签打印机和供应商 API。

界面通过 Crowdin 翻译，简体中文完成度很高，文档是英文。

在 0402 里，它和 Homebox 分工：Homebox 管整箱和整件的东西，InvenTree 管数数的小零件。矮货架上每个透明周转箱在 InvenTree 里是一个库位，箱口二维码扫码进箱，取三个 M6 铜嵌件就在手机上减三。坑是它功能偏重，一开始只建库位树和零件两张表，别急着上 BOM 和采购，否则录数据的热情撑不过一周。

sysadminsmedia/homebox ★ 7.1k 界面有中文

面向家庭用户的自托管物品库存系统，按位置、标签分类，带图片和维护记录

→ 每个周转箱在里面建一个位置，打印二维码贴箱口，扫码就跳到箱内清单，和 0801 数字孪生打通

Homebox 是面向家庭用户的自托管物品库存系统，最早由 hay-kot 开发，现在由 sysadminsmedia 接手维护，7.1k 星，是 selfhosted 圈子里做家庭物品清单最常被推荐的项目。它解决的问题是：家里的东西放在哪、什么时候买的、保修到几号、多久没用了，靠脑子记不住。

它的架构是 Go 后端加 Nuxt 前端，单个 Docker 容器就能跑，数据存 SQLite，资源占用很小。数据模型很朴素：位置是一棵树，位置里放物品，物品可以挂标签、照片、购买凭证、说明书附件、保修期和维护记录；每个位置和物品都能生成二维码标签，扫码直接跳到对应页面，还能批量导入导出 CSV。界面有中文翻译，手机浏览器上操作也顺手，社区更新频繁。

和 InvenTree 相比它轻得多，不管数量、不管 BOM，适合整件的东西。

在 0402 里，它是那些周转箱的目录：北条的每层货架、每个箱子在里面建成位置树，箱里的皮革边角、帆布卷、3D 打印线材各是一件物品，箱口的二维码由它生成后用 brother_ql 打印。扫一下就跳出黄铜配件、23 件、上次使用 6 月 3 日那种页面，取用时顺手在物品页记一笔。它和 0302 装备区共用一套实例，只是位置树的根节点不同，将来 0801 数字孪生也从它的 API 取数据。坑是位置树别建太深，三层够了，否则每次移箱都要改一串。

pklaus/brother_ql ★ 701 无中文

直接驱动 Brother QL 系列标签机的 Python 库，不用官方驱动，支持 USB 和网络

→ 写个脚本批量把箱名和二维码打成统一字体的标签，字体永远一致不会强迫症发作

brother_ql 是德国开发者 Philipp Klaus 写的 Python 库和命令行工具，701 星，直接实现了兄弟 QL 系列标签打印机的光栅打印协议。官方驱动只在 Windows 和 macOS 上好用，有了它，不装任何官方驱动，在命令行里就能把一张图片打成标签。

它的原理很干净：用户用 Pillow 把标签画成一张位图（文字、二维码、线条随便画），brother_ql 把位图转成打印机认识的光栅指令，再通过 USB（pyusb）、Linux 的 /dev/usb/lp 设备或网络端口发给打印机。命令行一句 brother_ql print -l 62 label.png 就打出来，标签宽度、型号、旋转都是参数。支持 QL-500 到 QL-1110NWB 的十几个型号，包括国内容易买到的 QL-800。仓库本身几年没大更新，但协议稳定，社区有基于它的网页版 brother_ql_web 和 Home Assistant 加载项。

没有中文资料，好在用法就一条命令。

在 0402 里，它跑在 0804 那台常驻的 M1 Mac 上：写一个几十行的脚本，从 Homebox 的 API 拉出所有箱子的名称和二维码内容，用同一款思源黑体统一字号排版，一次打完贴在箱口，字体永远一致。坑是标签纸型号要和命令里的宽度参数完全一致，62 毫米连续纸和 29 毫米切片纸不能混，否则打印机会红灯报错。

odoo/odoo ★ 52.8k 界面有中文 延伸

比利时 Odoo 公司的开源 ERP 套件：库存、采购、制造、销售、会计几十个模块一体，社区版免费自托管，国内中小企业用得很多

→ 材料仓库如果哪天要算成本、管采购和 BOM，InvenTree 之外可以看看正经 ERP 的库存模块怎么做，Odoo 是开源里最完整的一套

Odoo 是比利时 Odoo 公司维护的开源商业应用套件，用 Python 和 PostgreSQL 写成，52.8k 星，当前主线是 19 版，从 2005 年的 TinyERP 一路演化过来。它要解决的问题是：一家企业的库存、采购、销售、制造、会计、CRM 各用一套软件，数据对不上，Odoo 把这些做成同一个数据库上的几十个模块，装哪个用哪个。

它的工作方式是模块加工作流：核心 ORM 定义模型，每个模块在上面加字段、视图和业务规则；库存模块用仓库、库位、批次和移动单来记每一件物料的去向，支持条码扫描收货和盘点；采购模块按补货规则自动生成采购单；制造模块管 BOM、工单和领料；会计模块把所有单据自动记账。网页界面手机能用，有条码扫描专用页面；社区版开源可自托管。

生态上它的应用商店有几万个第三方模块，国内有大量实施商和中文社区，界面自带简体中文且本地化很完整；公司每年发一个大版本，非常活跃。

对 0402 来说它是延伸项目：仓库日常用 InvenTree 和 Homebox 就够，Odoo 太重。它的用法是两条：一是学习——看它的库存模块怎么定义库位、批次和补货规则，把这套思路简化后用到周转箱二维码和 0801 数字孪生库的字段设计上；二是备用——如果 PSK 盒子哪天从自用变成小批量售卖，胡桃木板、黄铜配件、皮革边角就成了要算成本的原料，用 Docker 在 0802 服务器上跑一份 Odoo 社区版，仓库、采购、BOM、销售一起上，每一块板子的成本从此有据可查。

nocodb/nocodb ★ 64.5k 官方中文 README 延伸

开源的 Airtable 替代品：把 MySQL、PostgreSQL 或 SQLite 变成带表格、看板、表单和 API 的智能电子表格，自托管一条 Docker 命令

→ 材料仓库那张木料清单、周转箱清单和半成品暂存表，用 nocodb 做成可以手机扫码填写的表格，比专门的库存软件更贴近实际习惯

NocoDB 是印度团队 NocoDB 公司维护的开源无代码数据库，用 TypeScript 和 Vue 写成，64.5k 星，是 GitHub 上最热门的 Airtable 替代品。它要解决的问题：很多人只想要一张能协作、能加附件、能手机填的表格，Excel 不擅长，Airtable 又按人头收费且数据在别人手里。

它的工作方式是给数据库套一层电子表格皮：它可以自带 SQLite，也可以连上已有的 MySQL、PostgreSQL，把每张表变成一个网格视图，字段类型包括文本、数字、单选、附件、关联、公式、条码和二维码；同一张表能切成表格、看板、日历、画廊和表单视图，表单可以发成链接让别人填写。每张表自动生成 REST API，Webhook 在新增或修改时通知外部系统。

生态上有 Docker 和群晖一键部署，README 有官方中文版，界面也有简体中文；发版频繁，2026 年仍很活跃。

对 0402 来说它是延伸项目：InvenTree 管零件，Homebox 管物品，但斜顶下那排木料架更像一张清单——木种、厚度、长度、剩余块数、进货日期、格位号。在 0802 服务器上跑一份 NocoDB，建一张木料表，字段里加一个二维码列自动生成每格的码，打印贴到木料架上；A 字架上的板材和楼梯口的半成品暂存箱各建一张表，用表单视图做成手机页面，取走一块板顺手扫码减一。API 和 Webhook 接进 HomeAssistant，某种木料低于两块时推送提醒补货。
