地堡 · 模块 0210 · 防灾食品

被问爆了！地堡储藏室这面架子能让我一个人吃 90 天

先进先出的食品货架，罐头、米、水按日期滚动，永远不过期。

⬜ 真实项目待设计 #防灾储备#pantry整理#先进先出#动手主义#码住

📐 它在哪、有多大

地堡东侧那间储藏室（≈1.65×2.45m，≈4㎡），北邻卫生间、南邻东南角的门口区；钢架 ≈2.4m 长靠储藏室东墙一整面摆，架前只留 ≈1m 站人取货的过道。

位置与尺寸依据 0008 户型图与空间标注 v1；≈ 为按图面比例预估、未实测。看户型图 →

🎬 沉浸式想象

储藏室里靠东墙那面 2.4 米长的钢架，从上到下是一整面“时间墙”。最上层是真空米砖和干面，中间三层是罐头，每一层的斜滑轨让新罐头从后面放进去、旧的自动滚到前面，标签朝外，日期用马克笔写得老大。最下层是 12 桶 18L 的水桶，桶上贴着换水日期。旁边挂着一块小白板：“库存 92 天 / 下次轮换 10 月 3 日”。你顺手拿了一罐前排的午餐肉——今晚炒饭用它——然后从背包里掏出一罐新的补到后面。这面墙从来不是为了灾难，是为了随时能安心。

✅ 设想方案清单

  1. ≈2.4m 长 × 2m 高的镀锌钢架靠储藏室东墙，5 层，最下层只放水，减轻上层承重
  2. 罐头层做 15° 斜滑轨（3D 打印导轨），后进前出，天然先进先出
  3. 米、面、豆用 5kg 真空砖 + 密封桶，桶盖贴 NFC 标签，一碰手机就看日期
  4. 12 桶 18L 饮用水 + 1 个便携净水器，每半年轮换一批
  5. 架子侧面挂小白板 + 磁吸卡片：库存天数、下次轮换日、缺货清单
  6. 0801 数字孪生里给每个 SKU 建档，到期前 30 天自动推送“该吃掉了”
  7. 留一格“PSK 应急包”：一个背包装 72 小时口粮，随时拎走

⚠️ 避坑提醒

  • 储藏室没窗也潮，罐头也会生锈，架子离墙 5cm，别贴墙摆
  • 水桶别全塞最下层同一侧，200 多公斤压偏了架子会歪
  • 别囤自己平时不吃的东西，轮换日会变成“扔东西日”

grocy/grocy ★ 9.5k 界面有中文

自托管的家庭食品和物资管理系统，管库存、保质期、最小库存、采购清单和条码，带 REST API

→ 罐头、米砖、水桶都建成 SKU，到期前 30 天自动提醒该吃掉了，先进先出它天生支持，库存天数也从它算

grocy 是德国开发者 Bernd Bestel 从 2017 年开始写的自托管家庭物资管理系统，9.5k 星，口号是“超越冰箱的 ERP”。家里囤的东西哪罐先过期、米还剩几袋，靠脑子记一定会漏，它把仓库软件那套 SKU、批次、保质期、最小库存搬进了家庭。

它是一个 PHP 写的网页应用，SQLite 存数据，一个 Docker 容器就能跑。核心是产品、库存条目和位置三张表：每次入库记数量和保质期，消耗时按最早到期的批次先扣，天生就是先进先出；每个产品可设最小库存，低于就自动进采购清单；到期前几天在首页高亮。支持条码，还管食谱、家务、设备保养。它有完整的 REST API，Home Assistant 的社区集成能把“即将过期数”“缺货数”做成传感器。界面有简体中文，NAS 圈中文教程很多。

在 0210 里它就是那面时间墙的账本：每种罐头、米砖、面、水桶建一个产品，位置按货架层填，保质期照罐身写；入库时扫条码或用手机 NFC 碰米桶盖直接打开该产品的入库页；取一罐吃掉就消耗一个，它自动扣最早到期的那批。0801 数字孪生里的“库存 92 天”由 HA 从它的 API 读各产品数量乘每日用量求和得出，到期前 30 天推送“该吃掉了”，缺货项进采购清单。坑是初次建档几十个 SKU 很枯燥，一次只建常吃的二十种，水桶和米砖用“开封 / 换水”当消耗事件记就行。

TomBursch/kitchenowl ★ 3.7k 界面有中文

自托管的采购清单和食谱管理应用，Flask 后端 + Flutter 客户端，有安卓 / iOS / 网页端，多人实时同步，可部分离线

→ 轮换日缺货清单直接生成采购单，去镇上补货时手机上勾一下，有原生 App 比 grocy 的网页顺手得多

KitchenOwl 是德国开发者 Tom Bursch 从 2020 年开始写的自托管采购清单应用，3.7k 星。购物清单要么写在冰箱贴上要么散在聊天记录里，它给一个家庭一份共享清单，谁加了什么、谁买了什么，所有人手机上实时同步，去超市勾一下就划掉。

架构是 Python Flask 写的后端加 Flutter 写的客户端，所以安卓、iOS、网页、桌面端都是同一套代码，App 在应用商店和 F-Droid 都能装。清单按超市分类排序；食谱模块一键把食材加进清单；还有每周餐单和开支分摊。部分离线可用。它有 REST API，Home Assistant 的集成能把清单当 todo 实体读写。界面有简体中文（Weblate 社区翻译），文档英文，更新很勤。

在 0210 里它是 grocy 的“出门那一半”：grocy 管货架上的账本，KitchenOwl 管补货那趟路。每次轮换日，HA 从 grocy 的 API 拉出缺货项，通过 KitchenOwl 的 API 写进“镇上采购”清单并按商店分好类；去镇上时手机开 App，买一样勾一样，回来扫码入库时 grocy 再销账。坑是两套系统各有一份产品名，HA 自动化用 grocy 的产品名做主键，KitchenOwl 只当纯文本清单，别指望它俩自动对齐库存。

Forceu/barcodebuddy ★ 604 无中文

grocy 的条码扫描配套工具，扫一下就入库、消耗或开封，不认识的条码自动去 OpenFoodFacts 查名字

→ 补货和取罐头时扫条码就完成出入库，不用每次打开网页手动改数量；有 HA 插件版，直接装在同一台小主机上

Barcode Buddy 是德国开发者 Marc Ole Bulling 写的 grocy 配套工具，604 星，一句话说明是“grocy 的条码系统”。grocy 自带的条码流程太啰嗦，每次都要打开网页、选产品、选操作、填数量；而在储藏室里你只想“扫一下，东西就进账了”。

它是一个 PHP 小服务，需要 grocy 的 API 密钥，可以 Docker 部署，也有 Home Assistant 插件版。工作方式是先设一个模式——入库、消耗、开封、加进采购清单——然后不停扫：扫到 grocy 里已有的条码就直接执行；扫到没见过的条码，它去 OpenFoodFacts 或 UPCitemdb 查商品名，列出来让你在网页里对到某个 grocy 产品，下次就认识了。模式本身也是条码，打印一张“模式卡”贴在架子上，扫“消耗”再扫罐头就完成一次出库，全程不碰手机。支持 USB 和蓝牙扫码枪、安卓 App 相机。文档英文。

在 0210 里它把货架变成“扫码即记账”：储藏室门内挂一支蓝牙扫码枪，架子侧面贴四张模式卡（入库 / 消耗 / 开封 / 缺货）；补货回来先扫“入库”再逐个扫罐头，做饭取罐头时扫“消耗”再扫罐身，grocy 自动扣最早到期那批。国产罐头有些条码查不到，第一次要手动对产品；没条码的水桶自己打印一张 grocy 条码贴上。坑是模式会保持到下次切换，扫完记得扫回“消耗”。

kiwix/kiwix-desktop ★ 1.4k 界面有中文 延伸

Kiwix 的桌面端：离线阅读 ZIM 格式的整站压缩包，整部中文维基百科、维基教科书、急救和农业资料都能装进一块硬盘

→ 防灾食品架旁边真正该备的还有一份离线知识：断网时整部维基百科和急救手册就在地堡的电脑里，Kiwix 就是干这个的

Kiwix 是瑞士非营利组织 Kiwix 从 2007 年维护的离线阅读项目，kiwix-desktop 是它的 Qt 桌面端，1.4k 星，兄弟仓库还有 kiwix-serve 命令行服务器和手机客户端。它要解决的问题是：维基百科这种人类知识总集依赖网络，没有网的地方（船上、山区、灾害中）就看不到；它把整个网站压成一个文件带走。

它的工作方式是：内容打包成 ZIM 格式，这是专门为离线整站设计的高压缩只读格式，全文索引也在里面，整部中文维基百科带图片大约 20 多 GB；kiwix-desktop 打开 ZIM 后像浏览器一样浏览和搜索，内置目录能直接从 Kiwix 内容库下载新的 ZIM，官方库里有各语言维基百科、维基医学、Stack Exchange 和一批急救与农业资料。kiwix-serve 则把 ZIM 用 HTTP 服务出来，局域网里所有设备用浏览器访问。

社区稳定，2025 年后仍有版本，界面翻译含简体中文，中文教程主要在离线知识和应急圈。

对 0210 它是延伸中的那格知识储备：钢架最上层是米砖，地堡电脑硬盘里是一份中文维基百科、维基医学、野外急救和食品保存的 ZIM，用 kiwix-serve 跑在 0802 的服务器上，断网时 0204 工作台和手机都能查。每半年轮换水桶的同时也更新一次 ZIM，写在小白板的轮换日旁边。PSK 应急包里的旧手机装 Kiwix 安卓版和一份精简 ZIM，随时拎走。注意完整维基百科下载很慢，挑一个夜里挂着。

meshtastic/firmware ★ 8.3k 无中文（社区教程多） 延伸

LoRa 无网通讯的开源固件：几十块钱的 ESP32 或 nRF52 LoRa 板组成自组网，手机蓝牙连上就能几公里外发短信和位置

→ 防灾备的不只是吃的，还有断网断电时和山谷另一头说上话的手段；Meshtastic 是最便宜也最成熟的离网通讯

Meshtastic 是 Kevin Hester 在 2020 年发起的开源离网通讯项目，固件仓库 8.3k 星，跑在 Heltec、LilyGO T-Beam、RAK 等几十种 LoRa 开发板上。它要解决的问题是：没有手机信号和 Wi-Fi 的地方（山里、海上、灾后），人和人之间怎么发一条短信和自己的位置。

它的工作方式是：每块板子是一个节点，用 LoRa 无线电在免许可频段以极低功率发送很小的数据包，节点之间自动转发形成网状网络，一条消息可以经几跳传到几公里甚至几十公里外；手机通过蓝牙连上自己的节点，App 里像发微信一样打字，消息端到端 AES 加密，带 GPS 的节点定期广播位置，地图上能看到所有节点在哪。一块 18650 电池能撑几天，加太阳能板就是永久中继站。它还有 MQTT 网关能把消息桥到互联网，有 Python API 可以写机器人。

社区非常活跃，2025 年后固件月更，README 英文，中文社区教程和国产开发板的资料很多。

对 0210 它是延伸的通讯储备：储藏室钢架上除了 72 小时口粮，再放两个 Meshtastic 节点，一个装进 PSK 应急包，一个固定在木屋屋顶接一块太阳能板做中继；地堡里的节点通过 MQTT 网关接进 HomeAssistant，平时当玩具，断网时它就是唯一的电话。和山谷里其他玩这个的人约好频道，就是一张本地应急网。注意地堡的混凝土墙对 LoRa 也是墙，地堡里的节点要把天线引到屋顶，不然只能和木屋里通。

openfoodfacts/openfoodfacts-server ★ 1.1k 界面有中文 延伸

Open Food Facts 的服务端：全球最大的开放食品数据库，扫条码就有配料、营养、Nutri-Score，API 免费可用

→ 罐头和米砖的 NFC 标签要录名字、保质期和营养信息，扫一下条码从 Open Food Facts 拉回来比手打快得多

Open Food Facts 是法国非营利组织在 2012 年发起的开放食品数据库，服务端仓库 1.1k 星，Perl 写成，数据库里有全球四百多万种食品。它要解决的问题是：食品包装上的配料和营养信息属于所有人，但没有一个开放的、任何人都能查和贡献的数据库，它就像食品界的维基百科。

它的工作方式是众包：用户用手机 App 扫条码，拍下正面、配料表和营养表，服务端用 OCR 识别配料，算出 Nutri-Score 营养等级和 NOVA 加工程度，数据以开放许可证发布；任何人都能通过 REST API 用条码查一个产品，返回名称、品牌、分量、配料、过敏原、营养成分和图片，也能整库下载。它的生态包括安卓和 iOS App、Python 和 JavaScript SDK，Grocy、KitchenOwl、Barcode Buddy 这些自托管库存工具都用它的 API 补全商品信息。

社区是全球性的，2025 年后服务端每周发布，网站和 App 有简体中文，中国市场的商品覆盖一般，进口食品和大品牌罐头基本都有。

对 0210 它是延伸的数据源：0210 已有的 Grocy 和 Barcode Buddy 扫条码时就是从它拉商品名和营养信息，钢架上罐头一到货扫一下，名称、分量、热量自动进库存，再由 0801 数字孪生按每人每天两千大卡算出库存天数写到小白板；国内小厂的罐头查不到就当场拍照贡献上去，下次就有了。注意它是公共数据库，自家的保质期和存放层这些信息不在它那里，存进 Grocy。
