沉浸式指挥室！一块大屏能看到整座房子在呼吸，它不属于任何一个房间

一整面数据墙加手机上的同一份仪表盘，八个区域的温度、水位、光照、鱼缸都在上面跳动。

📐 它在哪、有多大

它是跨区域的信息层：数据来自七个物理区域的每一个传感器，落在哪儿都行。设想版把主屏挂在地堡东侧储藏室的西隔墙（≈2.45m 长）上，面朝中央地毯和沙发：65 寸竖屏居中，两块 27 寸横屏分列，屏下一排实体开关；小主机和 UPS 藏在隔墙背后的储藏室里；手机、木屋吧台的平板、miniduck 的小屏都是它的分身。（原编号 0211，2026-09-09 随 08 虚拟空间设立重编；0008 未定位，设想落位）

🎬 沉浸式想象

东南角进门右手、储藏室隔墙那面墙，是一块 65 寸的竖屏加两块 27 寸小屏。中间是整栋房子的等距地图：木屋的柴火炉在闪红点，草地的滴灌刚开了 3 分钟，雨水罐 1,380L，鱼缸 25.3℃，地堡湿度 54%。左屏滚着一天的光照曲线，右屏是过去 7 天的用电和用水。你端着杯子站在屏幕前看了一分钟，什么都没动——它自己就在运转。屏幕角落有一行小字：“今天所有模块正常。”你有一种奇怪的踏实感，像看着一艘船的仪表盘，而这艘船是你自己造的。

✅ 设想方案清单

  1. 储藏室隔墙（面朝地毯）装 65 寸竖屏 + 两块 27 寸横屏，全部用 HomeAssistant 仪表盘驱动
  2. 中屏做整栋房子的等距地图，每个模块一个动态图标，状态异常就变色闪
  3. 左屏：光照 / 温湿度曲线（0201、0203、0306）；右屏：水电（0304、0603、0602）
  4. 屏幕下方一排实体开关：模拟阳光四场景、观影模式、全屋关灯，按下去有咔哒声
  5. 小主机（N100）跑 HA + ESPHome + 数字孪生数据库，UPS 保 30 分钟
  6. 手机端同一份仪表盘，出门也能看，但大屏只在地堡有——这是回家的理由
  7. 每天 22:00 屏幕自动切“夜航模式”，只剩黑底上几个红色数字

🔧 GitHub 上的成熟方案

按知名度（星数）优先、有中文版优先挑的开源项目，每个都在 2026-09 打开核实过存在。每个方案配一段科普介绍和一张铅笔风的“它怎么工作 + 怎么接进本模块”示意图。

home-assistant/core ★ 88k 有中文文档站

开源家庭自动化平台，本地控制、注重隐私，三千多个集成把所有设备抽象成实体

→ 全屋中枢就是它，三块屏、手机端和实体开关全靠它的仪表盘和自动化驱动，核心依赖

Home Assistant 是目前最流行的开源家庭自动化平台，2013 年发起，现由 Open Home Foundation 托管，88k 星，每月发一个版本，最新是 2026.6。它的核心主张是本地控制和隐私优先：所有设备状态都在自家主机里，不依赖厂商的云。

它的架构可以概括为集成→实体→自动化→仪表盘：三千多个集成把 ESPHome 节点、Zigbee 传感器、摄像头、NAS 之类接进来，统一抽象成实体，每个实体带状态和属性并记入历史数据库；自动化引擎用触发器、条件、动作三段式描述规则；仪表盘用 YAML 或可视化编辑器拼卡片，可以按屏幕分不同视图。中文方面，界面有完整简体中文，官方文档站只有英文。

在 0802 里它就是整个中枢：跑在储藏室的 N100 小主机上（Docker），八个区域的传感器全部经 ESPHome 原生 API 汇进来，三块屏各对应一个仪表盘视图，浏览器全屏就是大屏；屏下那排实体开关是 ESPHome 的二值传感器，按下触发场景自动化；22:00 的夜航模式是一条自动化切换视图和主题。注意历史数据库默认只留 10 天，曲线类实体要开长期统计或另存 InfluxDB；断网时它照常运转，但手机端远程访问要走 Nabu Casa 或自建反向代理。

ExperienceLovelace/ha-floorplan ★ 1.6k 无中文

HomeAssistant 卡片，把实体状态映射到 SVG 平面图元素上，规则驱动样式与点击动作

→ 中屏那张整栋房子的等距地图就用它做，模块异常变色闪烁靠它的 CSS 规则

ha-floorplan 是 Home Assistant 生态里做平面图仪表盘的老牌插件，1.6k 星，2026 年 4 月还在发版（v1.1.5）。它解决的问题是：默认的卡片列表看不出空间关系，一张自己家的图，哪里亮了、哪里冒红，一眼就懂。

它的工作方式是把一张 SVG 图里的元素和 HA 实体绑定：你在 Inkscape 或 Figma 里画好房子，给每个可交互的图形取一个 id，在 YAML 配置里写规则：某个实体状态变化时给这个 id 加什么 CSS 类、改什么样式、显示什么文字，点击或长按时调用什么服务。样式完全用 CSS 写，所以异常变红闪烁就是一个 keyframes 动画。它可以做成卡片也可以做成整页面板，通过 HACS 安装，有独立文档站，只有英文。

在 0802 里它负责 65 寸竖屏正中那张整栋房子的等距地图：先把 0008 那张全屋草图在 Inkscape 里重画成等距 SVG，每个模块一个图标组，柴火炉、雨水罐、鱼缸各绑一个实体，正常态是灰线稿，异常态由规则加上红色闪烁类；点击图标跳到该模块的二级页。坑有两个：SVG 里的文字要拆成 tspan 才能被规则改内容；图元 id 别用中文，否则规则匹配不稳。

piitaya/lovelace-mushroom ★ 5.1k 界面有中文

HomeAssistant 最流行的简洁风格仪表盘卡片集，17 种卡片、内置编辑器、零依赖

→ 左右两块小屏的温湿度、水电卡片用它排版，好看又不用写太多 YAML

Mushroom 是 Home Assistant 上最流行的仪表盘卡片集，由 Paul Bottein（piitaya）开发，5.1k 星，通过 HACS 安装，目标是不写太多 YAML 也能拼出好看的仪表盘。它解决的是原生卡片信息密度低、风格参差的问题。

它的做法是提供 17 种针对设备类型设计的卡片：灯、温控、风扇、窗帘、门锁、媒体播放器、人物、选择器、数字、更新，再加一个万能的模板卡和一排小药丸（chips）。每张卡都有内置的可视化编辑器，图标、颜色、布局、副标题点几下就配好，模板卡能用 Jinja 写任意文字和图标颜色，配合 Mushroom Themes 可以整体换风格，零外部依赖，深浅色都适配。项目持续更新，Weblate 有中文翻译，README 只有英文，但小红书上晒 HA 大屏的帖子多半在用它。

在 0802 里它负责左右两块 27 寸小屏：左屏光照和温湿度、右屏水电，每个数据一张模板卡，副标题写单位和更新时间，用 chips 在顶端排一行今天所有模块正常之类的状态药丸；曲线本身交给 HA 自带的 history-graph 卡，Mushroom 只管数字和标题。要克制：先只放真正会看的 10 个数，其余藏在二级页，不然就是看板疲劳。夜航模式用它的主题变量把背景切纯黑、字切红，配合 HA 的自动化在 22:00 换主题。

gethomepage/homepage ★ 32k 界面有中文 延伸

自托管起始页仪表盘：YAML 配置，靠 Docker 标签自动发现容器，一百多种服务集成能把 Jellyfin、Uptime Kuma、NAS 的实时数字摆在一页上

→ 屏墙上 HA 管传感器，但 0804 三台机器上的十几个服务谁在跑、跑得怎样，需要一页服务层总览，它是这类起始页里星最多的

homepage 是 gethomepage 组织维护的自托管起始页，32k 星，是近几年自托管圈里最流行的仪表盘之一。它解决的问题是：家里跑了十几个服务，每个都有自己的网址和状态页，需要一页把入口和关键数字都摆出来，打开浏览器第一眼就看到。

它用 Next.js 写成，配置是几个 YAML 文件：services 定义分组和卡片，widgets 定义顶部信息条，bookmarks 定义书签。最特别的是集成能力：一百多种服务有专门的小部件，填上地址和密钥，卡片上直接显示 Jellyfin 正在播放什么、Uptime Kuma 有几个监控在线、NAS 剩多少空间；再加上 Docker 标签自动发现，容器只要贴几行标签就会自动出现在页面上。请求经服务端代理，密钥不暴露到浏览器。

它更新很勤，2026 年仍是月度发版；界面经 Crowdin 翻译成四十多种语言，中文完整，文档是英文，但国内部署教程非常多。

在 0802 里它是延伸：三块屏由 HA 驱动，传感器这一层够了，缺的是服务层。做法是在 0804 的笔记本上跑 homepage，右屏的一个标签页嵌它：分组按机器排，NAS 一栏是 Jellyfin、Immich、存储余量，笔记本一栏是 HA、ESPHome、Uptime Kuma、Beszel，Mac mini 一栏是识别任务和 Ollama；哪个服务挂了卡片就变灰。手机上它也是入口页，出门时先看一眼再决定要不要点进 HA。

Lissy93/dashy ★ 26.4k 界面有中文 延伸

另一款自托管仪表盘：自带可视化编辑器，不用改 YAML 也能拖卡片，带状态检查、几十套主题、小部件、多页面和登录

→ 木屋吧台平板和手机需要一个不那么工程味的入口页，它的主题和编辑器更适合当分身；与 homepage 各有所长，值得一起学

Dashy 是英国开发者 Alicia Sykes 维护的自托管仪表盘，26.4k 星，和 homepage 是同一类东西，但取向不同：homepage 偏运维，靠 YAML 和自动发现；Dashy 偏个人化，主打可视化编辑和主题。它解决的问题同样是给一堆自托管服务做一个入口页。

它用 Vue 写成，一个 conf.yml 描述页面、分区和条目，但也可以完全不碰文件：界面里有编辑模式，拖拽卡片、改图标、加分区，保存后写回配置。它有状态检查，定时探测每个链接是否在线并在卡片角上亮灯；有几十套内置主题和自定义 CSS；有小部件系统，能嵌天气、系统负载、RSS、iframe；还有多页面、搜索快捷键、登录与按用户显示不同页面。

社区活跃，2026 年仍在更新，界面翻译含简体和繁体中文，文档是英文但很详尽；国内自托管圈把它和 homepage 并列为两大起始页。

在 0802 里它是延伸：屏墙归 HA，homepage 管服务层，Dashy 更适合做分身的入口。木屋吧台的平板和手机上放一个 Dashy 页面：第一页是几个大按钮，直接跳 HA 的各个视图；第二页用 iframe 嵌 Grafana 的水电曲线和 0801 的地图；主题用夜间黑底，22:00 之后和屏墙的夜航模式一个调子。它的状态检查还能顺手把各模块 ESPHome 节点的网页探一遍，掉线的卡片亮红灯，和 Uptime Kuma 互为备份。

ollama/ollama ★ 180.3k 无中文 延伸

本地跑大语言模型最省事的方式：一条命令拉取并运行 Qwen、Gemma、DeepSeek 等模型，提供 REST API，HA 有官方集成能把它当对话助手

→ 屏幕角落那句今天所有模块正常需要有人把几十个实体的状态读一遍再总结成一行，本地大模型干这个不联网也不花钱

Ollama 是 2023 年出现的本地大模型运行工具，180.3k 星，是 GitHub 上星数最高的项目之一。它解决的问题是：想在自己的机器上跑一个大语言模型，但不想折腾编译、量化和显存参数；它把这些包成一条命令，几分钟后就能对话。

它的核心是一个常驻服务：模型以 GGUF 格式从它的模型库拉取，底层推理引擎来自 llama.cpp，Mac 上走 Metal，有显卡走 CUDA 或 ROCm，没显卡用 CPU；对外开放一个 REST API，兼容 OpenAI 的接口格式，各种客户端和框架都能直接接。模型库里 Qwen、Gemma、DeepSeek 都有多个尺寸，8B 级别在 16GB 内存的 Mac mini 上能流畅跑。

HomeAssistant 有官方 Ollama 集成，可以把它设为 Assist 的对话代理并允许它读取和控制暴露的实体。文档是英文，中文教程遍地都是。

在 0802 里它是延伸：三块屏展示数据，但没有人替你读数据。在 0804 的 M1 Mac mini 上跑 Ollama，装一个 Qwen 8B 级别的模型，HA 的 Ollama 集成把七个区域的关键实体暴露给它，再建一条早晚各跑一次的自动化：把所有模块的状态发给模型，让它用一句话总结，写进屏幕角落那行小字，正常时就是今天所有模块正常，异常时会说柴火炉温度偏高、雨水罐传感器四十分钟没上报。同一个模型也是 0803 小鸭子断网时的后备大脑。
