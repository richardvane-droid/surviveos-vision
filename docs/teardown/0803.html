miniduck：4 个核心模块与逻辑

产品模块 1. 双足鸭身总成

鸭子的身体是一台 25cm 高、约 800g 的双足机器人：主控板（RK3566 或同级）跑步态策略，15 个总线舵机分布在两条腿、颈部和头部，50Hz 控制环里每一拍都在读 IMU 姿态、算下一步舵机角度。腿的外壳是自己 3D 打印的，脚底贴一层 TPU 防滑垫。胸腔里是电池、主控和一块无线充电接收线圈，所有重物尽量压低，重心低了才站得稳。

关键参数 / 组成

  • 总线舵机 ×15：腿 2×5、颈 3、头 2，串行一根线
  • RK3566 主控 + IMU，50Hz 控制环跑 ONNX 步态策略
  • 3S 锂电 2,000mAh，续航约 90 分钟，胸腔无线充电线圈
  • 外壳拓竹打印 PETG，脚底 TPU 防滑垫，摔不坏优先于好看

参考项目

pollen-robotics/microduck

产品模块 2. 头部感知与表情模组

头是鸭子和人打交道的地方：顶部一圈 4 麦阵列负责听（离舵机远，垫泡棉隔震），额头一颗广角摄像头负责认路和认人，两只眼睛是可寻址 RGB LED，胸口那块 1.28 寸圆屏兼做表情和数据窗。麦阵和摄像头的信号回到主控，语音那一路交给一块独立的 ESP32-S3（小智固件），主控只管走路和表情，两边各司其职，语音卡顿不会影响平衡。

关键参数 / 组成

  • 4 麦环形阵列 + 泡棉隔震，唤醒词本地识别
  • 广角摄像头 120°，识别充电窝反光标记与人脸（只认一个人）
  • 眼睛 RGB LED ×2，胸口 1.28 寸圆屏显示表情 / 数据
  • ESP32-S3 语音协处理器跑 xiaozhi 固件，通过串口与主控通信

参考项目

联动逻辑 3. 跨房间巡游与回窝

鸭子怎么在三个房间之间自己走：它没有激光雷达，靠一张手绘的“房间图”——每个房间几个反光标记（充电窝、门下通道口、坡道顶）和它们的相对方位。摄像头认出一个标记就知道自己大概在哪，然后按图里的顺序往下一个标记走；走通道口时切成低头慢步态，上坡道时切成前倾步态。电量低于 20%、或者主人 30 分钟没出现，就去最近的窝。

触发 · 阈值 · 兜底 · 出口

  • 触发：整点巡游 / 主人呼唤 / 电量 <20%
  • 路点=反光标记，摄像头识别 + IMU 航向推算
  • 通道口切“低头慢步”策略，坡道切“前倾”策略，摔倒自动起身
  • 兜底：连续 3 次找不到标记就原地蹲下并推送手机

主要实现路径

用 pollen-robotics/microduck 的 robotd 技能切换（walk / crouch / stand-up 等 ONNX 策略），路点导航自写一个小状态机，标记识别用 OpenCV ArUco

参考项目

pollen-robotics/microduck

联动逻辑 4. 问答与全屋数据播报

鸭子是 0802 全屋中枢的移动分身：你对它说一句“雨水罐还有多少”，ESP32 上的小智固件本地识别唤醒词后把语音送到大模型，大模型通过 MCP 调 HomeAssistant 的实体读数，把答案生成一句人话，鸭子用嘴说出来，同时胸口圆屏显示数字，眼睛按数据好坏变色。随口说的“记得买 M3 螺丝”会被识别成待办，写进 0801 的清单。

触发 · 阈值 · 兜底 · 出口

  • 唤醒词本地识别，之后才联网，物理静音拨杆一拨就聋
  • MCP 工具：读 HA 实体 / 写待办 / 触发场景，只开放白名单
  • 答案 ≤ 20 字，数据同时上圆屏，异常值眼睛变红
  • 失败兜底：3 秒没结果就说“我去问问大屏”并推送手机

主要实现路径

78/xiaozhi-esp32 的 MCP 客户端接 HomeAssistant 的 MCP Server，待办写入 HA 的 todo 实体，再由 0801 同步
